# 08: 원장형 입사일·기준방식 설정

**What to build:** 사용자가 입사일과 기준방식을 원장형 설정 화면에서 이해하고 변경하며, 기존
휴가 기록에 영향을 주는 변경은 결과를 확인한 뒤 선택할 수 있는 설정 흐름.

**Blocked by:** 02/잔액 원장 디자인 계약과 팝오버 셸.

**Status:** resolved

- [x] 현재 입사일과 기준방식이 고정된 라벨·값 구조로 읽힌다.
- [x] 입사일 기준과 회계연도 기준을 선택하고 저장할 수 있다.
- [x] 값이 바뀌지 않았거나 유효하지 않으면 저장 행동이 비활성이고 이유를 이해할 수 있다.
- [x] 입사일 변경으로 이전 휴가 기록과 조정이 영향을 받으면 보존하거나 삭제할 대상을 저장 전에 설명한다.
- [x] 삭제를 선택하면 기존 백업 계약이 유지되고, 보존을 선택하면 대상 기록이 남는다.
- [x] 저장 중 중복 조작이 막히고 실패 시 입력값과 설명이 유지된다.
- [x] 설정 저장 후 잔여와 관련 화면이 즉시 다시 계산된다.
- [x] 키보드와 보조 기술이 라벨, 입력 오류, 선택과 확인 상태를 이해할 수 있다.
- [x] Electron 제품 흐름이 기준방식 변경과 기록 보존·삭제 확인을 검증한다.

## Comments

- `SettingsTab`을 기본 설정 섹션으로 정리하고 입사일·기준방식에 고정 라벨, 선택지별 쉬운 설명과
  첫 발생 예시를 붙였다. 빈 값·실재하지 않는 날짜·변경 없음은 저장 전에 비활성화하고 상태
  문장으로 이유를 알리며, 입력·오류·저장 중·입사일 변경 확인을 ARIA 이름·설명·live region으로
  연결했다.
- 입사일을 앞당기거나 늦출 때 기존 `splitRecordsByHireDate`와 백업 전용 IPC를 그대로 사용해
  저장 전에 휴가 기록·조정 건수를 보여준다. `남기고 저장`은 대상을 보존하고 `지우고 저장`은
  기존 `data.json.bak` 계약을 유지한다. 설정 본문이 길어지면 본문만 스크롤한다.
- 격리 Electron 제품 흐름에서 동일값·빈 입사일, 기준방식 전환에 따른 잔여 `15 → 7.5`, 보존 후
  삭제, 백업 원본, 저장 실패 뒤 초안·재시도 경로와 이력 갱신을 확인했다. `pnpm verify` 결과
  core 123건과 desktop 30건을 포함한 전체 검사가 통과했다. 제품 흐름은 macOS 실행 증거이며
  Windows 실제 환경 검증을 대신하지 않는다.
