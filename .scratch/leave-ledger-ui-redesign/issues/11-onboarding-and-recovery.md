# 11: 첫 실행과 읽기 실패 복구

**What to build:** 입사일이 없는 사용자는 필요한 설정만 완료하고, 저장 파일을 읽을 수 없는
사용자는 정상 탭과 분리된 화면에서 원본을 보존하며 복구할 수 있는 두 경계 상태.

**Blocked by:** 10/원장형 데이터 관리와 파괴적 확인.

**Status:** ready-for-agent

- [ ] 입사일이 없으면 설정할 내용과 이유만 보이고 요약·이력은 사용할 수 없다.
- [ ] 첫 설정을 저장하면 설정 맥락을 유지하면서 정상 탭과 계산 결과가 활성화된다.
- [ ] 온보딩의 입력, 포커스와 오류 설명이 원장형 설정 계약을 따른다.
- [ ] 읽기 실패 상태에서는 정상 헤더와 탭을 표시하지 않아 사용할 수 없는 기능을 약속하지 않는다.
- [ ] 읽기 실패 종류가 사용자가 이해할 수 있는 문구로 구분된다.
- [ ] 백업 복구와 저장 파일 위치 열기 행동이 원본을 덮어쓰지 않는 기존 계약을 유지한다.
- [ ] 복구 성공 후 정상 상태가 다시 계산되고, 실패하면 복구 화면과 원본이 유지된다.
- [ ] 키보드와 보조 기술만으로 온보딩과 복구의 주요 행동을 완료할 수 있다.
- [ ] Electron 제품 흐름이 입사일 없는 데이터와 각 읽기 실패 fixture를 실제 앱에서 검증한다.
