# 10: 원장형 데이터 관리와 파괴적 확인

**What to build:** 사용자가 로컬 저장 파일의 위치를 확인하고 데이터를 내보내거나 가져오며,
기존 데이터를 바꾸는 조작은 결과와 백업을 이해한 뒤 실행하는 데이터 관리 흐름.

**Blocked by:** 08/원장형 입사일·기준방식 설정.

**Status:** ready-for-agent

- [ ] 저장 파일 위치 열기, 내보내기와 가져오기 행동이 설정 화면에서 명확히 구분된다.
- [ ] 내보내기 성공·취소·실패가 같은 화면에 설명되고 다른 설정값을 잃지 않는다.
- [ ] 가져오기는 바뀔 데이터와 백업 사실을 확인한 뒤에만 실행된다.
- [ ] 가져오기 취소는 현재 데이터와 화면 상태를 바꾸지 않는다.
- [ ] 가져오기 실패는 기존 원본을 덮어쓰지 않고 사용자가 다음 행동을 이해할 수 있게 설명한다.
- [ ] 더 새로운 저장 형식이나 읽을 수 없는 파일을 임의로 변경하지 않는다.
- [ ] 파일 대화상자가 열려 있는 동안 팝오버 수명 주기와 포커스가 기존 계약을 유지한다.
- [ ] 진행 중에는 충돌하는 데이터 조작이 비활성이고 완료 후 상태가 갱신된다.
- [ ] Electron 제품 흐름이 위치 열기, 내보내기와 가져오기의 성공·취소·실패 경계를 검증한다.
