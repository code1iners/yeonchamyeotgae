# 10: 원장형 데이터 관리와 파괴적 확인

**What to build:** 사용자가 로컬 저장 파일의 위치를 확인하고 데이터를 내보내거나 가져오며,
기존 데이터를 바꾸는 조작은 결과와 백업을 이해한 뒤 실행하는 데이터 관리 흐름.

**Blocked by:** 08/원장형 입사일·기준방식 설정.

**Status:** resolved

- [x] 저장 파일 위치 열기, 내보내기와 가져오기 행동이 설정 화면에서 명확히 구분된다.
- [x] 내보내기 성공·취소·실패가 같은 화면에 설명되고 다른 설정값을 잃지 않는다.
- [x] 가져오기는 바뀔 데이터와 백업 사실을 확인한 뒤에만 실행된다.
- [x] 가져오기 취소는 현재 데이터와 화면 상태를 바꾸지 않는다.
- [x] 가져오기 실패는 기존 원본을 덮어쓰지 않고 사용자가 다음 행동을 이해할 수 있게 설명한다.
- [x] 더 새로운 저장 형식이나 읽을 수 없는 파일을 임의로 변경하지 않는다.
- [x] 파일 대화상자가 열려 있는 동안 팝오버 수명 주기와 포커스가 기존 계약을 유지한다.
- [x] 진행 중에는 충돌하는 데이터 조작이 비활성이고 완료 후 상태가 갱신된다.
- [x] Electron 제품 흐름이 위치 열기, 내보내기와 가져오기의 성공·취소·실패 경계를 검증한다.

## Answer

- `DataSection`을 저장 파일과 가져올 저장 파일의 두 행동 묶음으로 나누고, 위치 열기·내보내기·가져오기 진행 상태와 완료·취소·실패 안내를 같은 설정 화면에 남겼다. 파일 경로는 코드용 글꼴로 표시하며 실패에는 다음 행동을 함께 설명한다.
- 가져오기는 파일 선택 전에 전체 교체와 `data.json.bak` 백업을 확인한다. 확인·네이티브 파일 대화상자 취소 시 저장 원문과 설정 입력을 보존하고, 조건부로 사라지는 가져오기 버튼도 논리적 이름을 기억해 포커스를 복귀시킨다.
- `withPopoverHeld` 기존 계약을 유지한 채 대화상자 진행 중 세 데이터 행동을 잠그고 팝오버를 유지한다. 파일 관리자 호출 뒤 비동기 blur도 짧게 정착시킨 뒤 포커스를 복귀한다. 가져오기 성공은 셸의 상태 푸시로 설정·잔여·이력을 갱신하며, 읽을 수 없거나 더 새로운 파일은 파싱 전에 멈추고 원본을 덮지 않는다.
- `revealDataFile`은 폴더 열기 실패를 렌더러에 전달하고, 내보내기 실패는 기술적 파일 오류 대신 다시 고를 위치를 안내하도록 정리했다. 저장 형식·스키마·마이그레이션·로컬 파일 위치는 변경하지 않았다.
- `apps/desktop/DESIGN.md`에 데이터 관리의 구조·확인·진행·피드백 계약을 추가했다. 실제 Electron 제품 흐름에서 파일 관리자 호출, 내보내기 완료·취소·실패, 가져오기 확인·취소·성공·실패와 진행 중 잠금을 검증했다.
- 검증은 제품 흐름 `28/28` 통과와 `pnpm exec turbo run lint typecheck test --force --concurrency=1` `6/6` 작업 성공(코어 123개·데스크톱 38개 테스트)으로 마쳤다.
- 제품 흐름은 격리된 사용자 데이터와 결정론적 대화상자 결과를 사용해 macOS에서 실행한 증거이며, Windows 실제 팝오버·파일 관리자 동작 검증을 대신하지 않는다.
