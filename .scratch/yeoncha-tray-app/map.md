# Wayfinder Map: 연차몇개(yeonchamyeotgae) 데스크톱 트레이 앱

Labels: `wayfinder:map`

## Destination

`to-spec`이 산출한 **v1 스펙 문서 1개**(`.scratch/yeoncha-tray-app/spec.md`)와 **셸 프레임워크 선택 ADR 1개**(`docs/adr/`). 구현 에이전트가 이 둘만 받아서 빈 저장소에 프로젝트를 스캐폴딩하고 v1을 완성할 수 있는 수준이어야 한다.

v1은 macOS·Windows 트레이 앱이며, 연차 산정 코어는 플랫폼 독립 TypeScript 패키지로 분리해 v2 PWA에서 그대로 재사용한다. v1은 개인 도구지만 연차 규정은 하드코딩하지 않고 설정값으로 둔다.

## Notes

- **도메인**: 한국 근로기준법상 연차 유급휴가(제60조). 발생·사용·소멸의 날짜 산술이 제품의 전부다.
- **모든 세션이 참조할 Skill**: `comment-style`, `ui-design`(UI 티켓), `domain-modeling`(용어가 흔들릴 때), `grilling`(결정 티켓)
- **트래커**: 로컬 마크다운. `docs/agents/issue-tracker.md`의 Wayfinding operations 규약을 따른다.
- **언어**: 모든 문서와 티켓은 한국어.
- **확정된 전제** (재논의 금지, 목적지 재설정 시에만):
  - 코어 계산 엔진은 **순수 TypeScript 패키지**. Rust/WASM 아님. 브라우저·Node·웹뷰 어디서든 동작해야 한다.
  - UI는 **React**.
  - 배포는 **GitHub Release**. AI 에이전트가 OS별 바이너리를 함께 업로드한다. (정하는 것은 *누가 하는가*이지 이벤트가 아니다 — [10번](issues/10-release-build-pipeline.md)이 릴리스 트리거를 `v*` 태그 푸시로, main 푸시는 검증 전용으로 갈랐다. 태그를 미는 것도 에이전트다.)
  - v2는 Next.js 기반 **PWA**가 유력하다. 코어 패키지가 그대로 넘어갈 수 있어야 한다.
  - **잔여 = 발생 − (사용 + 예정)**. 예정된 휴가도 잔여에서 차감한다.
  - **진짜 단순한 앱이다.** 기능을 늘려 복잡해지는 것을 명시적으로 거부한다. 기능 추가 제안은 "이게 없으면 잔여가 틀리는가"를 통과해야 한다.
  - **용어는 [`CONTEXT.md`](../../CONTEXT.md)가 유일한 출처다.** 모든 티켓·스펙·코드가 이 용어를 쓴다.
- **이 지도는 계획용이다.** 티켓은 결정을 낳고, 코드를 낳지 않는다. 예외는 `prototype` 티켓의 버릴 코드뿐이다.

## Decisions so far

- [01. 근로기준법 연차 산정 규칙 조사](issues/01-labor-law-accrual-rules.md): 1년 미만은 1개월 개근당 1일(최대 11일), 1년+1일 시점에 15일 발생(누적 발생 총량 26일이나 동시 보유는 아니다 — [03번](issues/03-leave-domain-model.md)에서 교정), 3년차부터 2년마다 1일 가산(상한 25일), 발생 후 1년 미사용 시 소멸. 회계연도 기준 첫해 비례부여는 법정이 아닌 관행이므로 설정값이어야 한다.
- [02. 코드서명·SmartScreen 실태 조사](issues/02-code-signing-and-smartscreen.md): macOS는 연 $99 + notarization으로 경고가 완전히 사라지지만, Windows는 2024년부터 EV 인증서도 SmartScreen 즉시 평판을 주지 않아 **돈으로 경고를 없앨 수 없다**. 따라서 v1은 양쪽 다 서명하지 않고 README 우회 안내로 간다.
- [03. 연차 도메인 모델 확정](issues/03-leave-domain-model.md): 발생은 소멸일을 가진 레코드 여러 건(숫자 하나가 아니다), 휴가 기록은 하루 1건·0.25일 단위, 사용·예정은 날짜에서 파생, 연차 연도도 파생, 사용자 조정은 덮어쓰기가 아니라 별도 레코드 덧붙이기. 이월은 조정으로 흡수한다. 용어집은 [`CONTEXT.md`](../../CONTEXT.md).
- [04. 연차 산정 규칙 사양 확정](issues/04-accrual-rule-spec.md): 잔여는 합계 뺄셈이 아니라 **배정**으로 구한다(각 휴가 기록이 어느 발생분에서 나갔는지 정한다) — 그러지 않으면 겹치는 발생분에서 잔여가 하나로 결정되지 않고 매년 1월에 이중 차감이 난다. 차감은 소멸 임박 순, 소멸일은 마지막 사용 가능일, 회계연도 첫해 비례부여는 `15 × 완성개월수/12`로 절사가 필요 없다(항상 0.25 배수). 잔여는 음수를 허용해 초과를 노출하되 그 발생분이 소멸하면 초과도 사라진다. 조정 레코드는 발생일·소멸일을 사용자가 넣는다. 검증 케이스 14건 포함.
- [05. 셸 프레임워크 결정: Tauri vs Electron](issues/05-shell-framework-adr.md): **Electron**. 가른 것은 번들·메모리가 아니라 **Windows 트레이 숫자 렌더링 경로**다 — Electron은 canvas → `nativeImage`로 네이티브 모듈 0개·전부 TypeScript(왕복 0.9ms)인데, Tauri는 Rust에서 글자를 래스터화해야 해서 저장소의 유일한 Rust 코드가 "트레이에 숫자 그리기"가 된다. 실측: DMG 120.8MB, 유휴 풋프린트 114MB, 우리 코드 201KB. 트레이·팝오버·값반영 메커니즘 전부 macOS에서 확인. Tauri 프로토타입은 만들지 않았고 Windows는 실행하지 못했다. `electron-builder`가 묻지 않고 로컬 인증서로 자동 서명하므로 파이프라인에서 명시적으로 꺼야 한다.
- [06. 트레이 표시 사양](issues/06-tray-display-spec.md): Windows 알림 영역의 정사각 제약은 **사실이다**(Win32 `SM_CXSMICON` 계약 + Electron 메인테이너 답변 + Win11에서 deskband 제거). 정사각 예산은 **편한 두 글자**이고 병목은 높이가 아니라 폭이다 — 16px에서 2글자는 cap 9px, 3글자 5.4px, 5글자 3.3px(죽는다). 따라서 **macOS는 잔여를 그대로**(`-24.75`), **Windows는 내림 정수만**(`-25`) 띄우고, 정확한 값은 툴팁과 팝오버가 갖는다. 아이콘·단위 표기 없이 숫자만. `Math.trunc`가 아니라 **`Math.floor`** 다 — trunc는 `-0.25`를 `0`으로 만들어 04번이 의도한 음수 노출을 지운다. 비대칭은 셸 분기가 아니라 코어의 `formatTrayLabel(balance, { maxGlyphs })` **예산 파라미터**로 표현한다. 자정·절전 복귀·시각 변경에 재계산하며, 그러려면 코어가 "오늘"을 인자로 받아야 한다. Windows 실물 검증은 못 했다.
- [07. 팝오버 UI 사양](issues/07-popover-ui-spec.md): **탭 3개(요약/이력/설정), 폭 380px, 별도 창 없음.** 등록은 `[휴가 등록] → 달력 시트 → 날짜 한 번 클릭 → 단위·메모` 3클릭이고 기간은 2단계에서 늘려 5클릭(하루 1건씩 펼쳐 넣는다). 달력이 두 몫을 한다 — 등록 시트이자 이력 탭의 두 번째 뷰(리스트와 전환). 4줄의 `예정`에는 배정분만 적고 내년 발생분 몫은 각주로 뺀다(총량을 적으면 4줄이 검산되지 않는다). 설정·조정은 팝오버 안 탭이고, 입사일이 없으면 설정 탭만 활성이며 조정 섹션은 숨는다. 소멸을 알아채는 경로는 발생분 행의 D-day와 이력 달력의 소멸일 밑줄 둘뿐이다. 높이는 고정하지 않고 탭 내용에 맞춘다. `[오늘]` 바로가기는 넣지 않아 가장 흔한 조작이 3클릭인 것이 남긴 구멍이다. Windows 실측은 못 했다.
- [08. 데이터 저장 형식 결정](issues/08-storage-format.md): **단일 JSON 파일 `data.json`**(userData 고정), 내보내기 파일이 곧 저장 파일이다. SQLite+Prisma를 기각한 것은 규모가 아니라 세 가지가 확정 전제를 건드리기 때문이다 — Prisma가 브라우저에서 안 돌아 v2가 검증 규칙을 다시 쓰게 되고, 05번이 Electron을 고른 근거인 "네이티브 모듈 0개"가 무너지고, 내보내기 포맷이 저장 포맷과 갈린다. 코어는 `parse`/`serialize` 순수 함수 둘만 갖고 I/O·백업·오류 화면 순서는 셸이 짠다. `schemaVersion`이 실제로 하는 일은 마이그레이션 체인(v1엔 비어 있다)이 아니라 **미래 버전 거부**이며, 이것이 SQLite를 썼어도 손으로 만들어야 했을 유일한 실재 손실 경로다. **읽지 못한 파일에는 쓰지 않는다**가 나머지를 결정한다 — 백업은 파괴적 조작 직전에만 남기고, 파서는 구조만 보며 도메인 이상치는 입력 UI가 막는다. 파일 없음 = 입사일 없음이라 코어에 `null` 분기가 없다. 이직은 입사일 교체 + 이전 기록 삭제 여부를 묻는 것으로 끝내고 회사 개념을 만들지 않는다.

- [09. 프로젝트 구조와 날짜 라이브러리 결정](issues/09-project-structure.md): **pnpm workspace + Turborepo, 패키지 둘**(`packages/core` + `apps/desktop`)이고 코어는 **빌드하지 않는다** — `exports`가 `./src/index.ts`를 직접 가리키는 Just-in-Time 패키지다. 워크스페이스를 고른 근거는 패키지 수가 아니라 **경계를 pnpm이 강제한다**는 것이다(코어가 `electron`을, 셸이 미선언 의존성을 import하면 `TS2307`로 막히는 것을 실측했다). `apps/web`이 나중에 붙는 것은 이 선택을 흔들지 않고 더 세게 만든다 — 소비자가 늘수록 "코어를 다시 빌드하는 것을 잊어 **잔여**만 조용히 틀리는" 함정이 는다. 날짜는 **Temporal**(`temporal-polyfill`을 정식 의존성으로, 네이티브가 있는 렌더러에서도 써서 환경 분기 0)이며 04번 케이스 M·완성 개월 수·윤년 `+1년 −1일`이 **예외 코드 0줄로** 통과하는 것을 돌려 확인했다. date-fns·dayjs 기각 사유는 크기가 아니라 `Date`가 시각과 시간대를 끌고 온다는 것이다. **"오늘"은 고정 `Asia/Seoul`** — v1과 v2가 같은 파일에서 같은 숫자를 내야 하기 때문이다. 셸 빌드는 `electron-vite` 5 + Vite 7(6은 베타뿐이고 Vite 8이 주는 게 없다), 테스트는 Vitest 4로 **코어만**(seam 셋: 계산·표시·직렬화), 린트·포맷은 Biome, 타입체크는 TS 7.0.2, 런타임은 Node 24 LTS. 검증은 `pnpm verify` 하나(웜 0.49s)이고 **`turbo run build`는 lint·typecheck·코어 테스트를 전부 통과해야** 산출물을 낸다 — lint를 turbo 태스크로 둘지에 대한 내 최초 판단은 실측으로 뒤집혔다. 스캐폴딩에서 반드시 밟는 함정 7개를 기록했다(turbo 캐시는 git 저장소가 있어야 동작한다, `allowImportingTsExtensions`, Biome이 `.gitignore`를 안 본다 등). `electron-vite` 통합과 Windows는 실행하지 못했다.

- [10. GitHub Release 빌드 파이프라인 설계](issues/10-release-build-pipeline.md): **워크플로 둘**이다 — `ci.yml`이 main 푸시·PR마다 macOS·Windows 양쪽에서 `pnpm verify` + `pnpm build`를 돌리고(`fail-fast: false`), `release.yml`이 `v*` 태그 푸시에만 패키징한다. main 푸시마다 릴리스하지 않는 이유는 소음이 아니라 **버전**이다(같은 버전의 릴리스가 여럿 생긴다). 태그에만 걸면 main이 무검증이 되므로 검증을 따로 뗀 것이고, 그 Windows 잡이 05·06·07·09번이 공통으로 남긴 "Windows에서 아무것도 실행하지 못했다"를 커밋 단위로 좁히는 유일한 장치다. **구조적 결정은 "쓰는 잡이 하나"**다 — `gitHubPublisher.ts`의 `createRelease()`에 422 `already_exists` 재시도가 없어(422 처리는 에셋 업로드 경로에만 있다) 두 러너가 동시에 publish하면 확률적으로 한쪽이 죽는다. 그래서 빌드 잡은 `--publish never` + 아티팩트만 올리고, 수집 잡 하나가 `softprops/action-gh-release@v3`으로 만든다(에이전트가 실패한 워크플로를 **재실행**하는 것이 멱등이어야 해서 `gh release create`가 아니다). 산출물은 **macOS arm64 DMG 하나 + Windows NSIS 하나** — universal은 arm64 러너에서 두 번 패키징 후 병합이라 **x64 사용자 0명을 위해 실제 사용자의 다운로드만 키우고**, x64 러너는 유료 large 계열인 데다 pnpm 11이 darwin-x64 바이너리를 배포하지 않아 09번 툴체인이 그 경로를 막는다. 서명은 `mac.identity: null`(환경변수가 아니다 — 소스상 키체인 조회 **전에** 반환하므로 05번의 자동 서명 사고가 로컬·CI 양쪽에서 막힌다) + `win.signExecutable: false`(`signAndEditExecutable: false`는 12번 아이콘까지 꺼진다). **켤 때 `identity: null`을 지우지 않으면 `CSC_LINK`를 넣어도 조용히 서명되지 않는다.** 버전의 유일한 출처는 `apps/desktop/package.json`이고 태그는 `v` + 그 값이며 릴리스 잡이 일치를 검사한다. **09번을 두 군데 교정한다**: 플랫폼별 lockfile 문제는 **존재하지 않고**(pnpm이 win32 optional 패키지를 전부 lockfile에 적는 것을 실측), `allowBuilds`에 필요한 건 `electron`이 아니라 **`esbuild: true`**다(Electron 42부터 postinstall이 없다 / 없으면 install이 종료 코드 1). 그리고 `@yeoncha/core`를 **`devDependencies`에 두면** electron-builder의 `--prod` 수집과 09번 5절의 `externalizeDepsPlugin` 함정이 **한 줄로 동시에 풀린다** — `apps/desktop`의 런타임 `dependencies`가 비는 것이 검사 가능한 불변식이 된다. 워크플로를 실제로 돌리지 못했고 Windows는 여전히 미검증이다. 1차 자료는 [`research/10-release-pipeline-findings.md`](research/10-release-pipeline-findings.md).

- [12. 앱·트레이 아이콘 글리프 확정](issues/12-icon-glyph.md): **트레이 글리프와 앱 아이콘은 별개의 두 그림이다** — 하나에서 파생시킬 수 없다. 품질이 서로 반대인 것을 실측했다: 달력은 512px 앱 아이콘으로 좋고 16px에서 고리가 상단 띠에 먹혀 뜻을 잃으며, 대시는 16px에서 완벽하고 512px에서 「빼기 버튼」이 된다. 그리고 **512px 앱 아이콘을 16px로 축소하면 파란 얼룩**이라 [06번](issues/06-tray-display-spec.md) Q4의 "입사일 미설정 = 앱 아이콘"은 그대로 구현할 수 없다 — 그 자리에 들어가는 것은 세 번째 그림이다. 그래서 **트레이 글리프는 가로 대시 하나**(`w = max(2, round(size×0.56/2)×2)`, `h = max(2, round(size×0.125/2)×2)`, 16px에서 8×2)이고 **앱 아이콘은 시스템 블루 squircle + 흰 달력**이다. 대시가 이긴 이유는 이 티켓이 "장식이 아니라 상태 표시"라고 못 박은 것이다 — 대시는 아이콘이 아니라 **비어 있는 숫자 자리**이고, 다른 후보는 전부 "무슨 앱인가"를 말하려다 16px에서 실패한다. **폭·두께를 짝수로 강제**하는 것이 이 후보의 존재 이유를 지킨다(홀수면 반 픽셀이 남아 안티에일리어싱이 생기고, "번지지 않는다"는 유일한 장점이 사라진다). 16px에서 사는 획의 일반 규칙도 나왔다: **축에 정렬된 정수 픽셀 획뿐**이다 — 1px 곡선(야자수)은 40% 회색으로 번지고, 획 여섯(한글 「연」)은 서로 붙는다. **트레이 글리프에는 아이콘 파일이 없다** — 06번의 canvas → `nativeImage` 경로를 그대로 타므로 파일이 아니라 함수이고, "Windows는 테마별 두 장"은 파일 두 개가 아니라 `tone` 인자 하나다(macOS는 `setTemplateImage(true)` 한 장으로 끝). `nativeTheme.on('updated')`가 **값이 실제로 바뀔 때만** 발화하는 것을 확인했다. 온보딩(07번 설정 탭)에는 글리프를 넣지 않는다 — 방금 그 글리프를 눌러 들어왔고, 07번이 "장식 없음"을 정했다. 10번의 `win.signExecutable: false` 근거가 이제 완결된다(붙일 아이콘이 생겼다). Windows 실물과 macOS 메뉴바의 템플릿 반전은 여전히 눈으로 확인하지 못했다.

- [11. 스펙 문서 작성](issues/11-write-spec.md): **목적지에 도달했다.** 산출물은 [`spec.md`](spec.md)(`ready-for-agent`)와 ADR **둘**이다 — 목적지가 명시한 [셸 프레임워크(Electron)](../../docs/adr/0001-electron-as-shell-framework.md)에 [날짜 라이브러리(Temporal)](../../docs/adr/0002-temporal-plaindate-for-dates.md)를 더했다. 두 번째 ADR을 만든 근거는 세 조건 중 **되돌리기 비용의 비대칭**이다 — 폴리필→네이티브는 import 한 줄이지만 `Temporal`→`Date` 기반은 코어의 모든 날짜 산술을 다시 쓰는 것이고 그게 제품 전부다. 게다가 "렌더러엔 네이티브가 있으니 폴리필을 빼자"와 "시간대를 로컬로"는 둘 다 **최적화로 보이는 모양**이라 되돌리기 쉽고 되돌리면 v1과 v2가 다른 **잔여**를 낸다. 반면 10번의 "릴리스를 쓰는 잡이 하나"는 ADR로 만들지 않았다 — 되돌리기가 CI 파일 한 줄이고 **그 한 줄이 있는 자리에서 주석이 같은 일을 하며**, 코드베이스를 관통하지 않는다(ADR을 늘리면 ADR을 읽지 않게 된다). 이유는 스펙 8.2절 본문이 갖는다. 스펙은 `to-spec` 템플릿에 절 하나를 더했다 — **반드시 밟게 되는 함정 15개**다. 그리고 "파일 경로를 넣지 마라"를 7·8절에서 **의도적으로 어겼고 왜 어기는지를 본문에 적었다**(완료 조건이 "스펙만 읽고 스캐폴딩을 시작할 수 있다"이므로 파일 트리 없이는 성립하지 않는다). 종합 중 **새 결정이 필요해진 자리는 없었다** — 앞선 티켓이 어긋나게 적어둔 두 곳(트레이의 입사일 미설정 상태, `externalizeDepsPlugin`의 `exclude`)은 12번·10번이 이미 교정을 명시해 반영일 뿐이었다. "앞선 티켓 문구를 그대로 옮기면 틀리는" 자리 다섯 개를 스펙 한 절에 모았다.
