# 25. 휴가 등록 흐름

Type: task
Status: resolved
Blocked by: 24

## What to build

휴가를 남기는 비용을 낮추는 흐름. **오늘 연차를 썼다는 것이 3클릭**이고 사흘 휴가가 5클릭이다.

```
[휴가 등록] → 달력 시트 → 날짜 클릭 → 단위·메모 → [등록]      하루: 3클릭
                              ↘ [기간으로] → 종료일 클릭 ↗       기간: 5클릭
```

- **날짜를 한 번 누르면 그 하루로 확정**되고 바로 2단계로 넘어간다. 기간은 2단계에서
  `[기간으로]`를 눌러 종료일을 하나 더 고른다. 흔한 쪽(하루)을 짧게 두는 선택이다([스펙 5.2절](../spec.md)).
- 2단계는 `종일 / 반차 / 반반차` + 메모(선택) + 기간일 때만 `주말 제외`(**기본 켜짐**).
- **기간은 UI가 하루 1건씩 펼쳐 넣는다.** 3/20~3/24를 주말 제외로 넣으면 휴가 기록 **3건**이 생긴다.
  기간 레코드를 만들지 않는다 — "월 종일 + 화 반차"를 표현할 방법이 없다(3.9절).
- 시트는 팝오버를 덮는다. 즉 **등록은 모드 전환**이다.
- **`[오늘]` `[내일]` 바로가기를 만들지 않는다.** 진입은 달력 하나다. 가장 흔한 조작이 3클릭인
  것은 **의도적으로 남긴 구멍**이며 써보고 거슬리면 다시 검토한다.
- **끌어서 기간 지정도 하지 않는다** — 380px 팝오버의 셀에서 오조작이 생긴다.

**달력은 코어의 seam이 아니다**(7.7절). "그 달의 1일이 무슨 요일인가", "그 달이 며칠인가",
"월 이동"은 `PlainDate.dayOfWeek` / `.daysInMonth` / `.add({ months: 1 })`이 직접 준다.
**코어에 함수를 만들지 마라.** 이 달력 컴포넌트는 26번의 이력 달력 뷰가 재사용한다.

**하루 1건 불변식**을 UI가 지킨다 — 이미 기록이 있는 날짜에 또 넣으면 파서가 거부한다(16번).

## Acceptance criteria

- [x] `[휴가 등록]`에서 달력 시트가 팝오버를 덮으며 열린다
- [x] 날짜를 한 번 누르면 그 하루로 확정되고 2단계로 넘어간다 — 등록까지 3클릭이다
- [x] 2단계에 `종일 / 반차 / 반반차`와 메모가 있고 각각 1 / 0.5 / 0.25로 저장된다
- [x] `[기간으로]` → 종료일 클릭으로 기간이 되고 등록까지 5클릭이다
- [x] 기간에서 `주말 제외`가 **기본 켜짐**이고, 3/20~3/24를 넣으면 휴가 기록이 3건 생긴다
- [x] 저장된 것이 기간 레코드가 아니라 **하루 1건짜리 여러 건**이다
- [x] 달력 격자가 한 주 7칸 × 48px로 380px에 들어간다
- [x] 이미 기록이 있는 날짜에 중복 등록되지 않는다
- [x] `[오늘]`·`[내일]` 바로가기와 드래그 기간 지정이 **없다**
- [x] 달력 계산이 `Temporal.PlainDate`의 속성으로 되어 있고 코어에 달력 함수를 추가하지 않았다
- [x] 등록 직후 트레이 숫자와 요약 탭이 갱신된다

## Comments

- **시트는 오버레이가 아니라 화면 교체다.** `App.tsx`가 `entryOpen`일 때 헤더·탭·본문 대신
  `LeaveEntrySheet` 하나를 그린다 — "시트는 팝오버를 덮는다 = 등록은 모드 전환"을 z-index가
  아니라 분기로 옮겼다. 높이 보고용 뿌리 요소는 그대로라 ResizeObserver가 살아 있다.
- **기간 펼치기는 렌더러의 순수 모듈 `entry-dates.ts`다.** 주말 제외와 기존 기록 건너뛰기,
  역순 정규화가 여기 있고 vitest 7건이 고정한다 — desktop 패키지에 이 티켓으로 vitest가
  처음 붙었다(코어의 seam이 아니므로 코어로 보내지 않았다).
- **이미 기록이 있는 날짜는 달력에서 비활성이고, 기간 안에 끼면 펼치기가 건너뛴다.**
  두 겹이라 시작·종료로도 못 고르고 사이에 있어도 빠진다. 며칠이 만들어지는지는 등록 전에
  `휴가 기록 N건을 만듭니다`로 보인다 — 0건이면 `[등록]`이 비활성이다.
- **종료일을 시작일보다 앞으로 골라도 오류가 아니다.** 펼치기가 순서를 정규화한다.
- **주말 제외는 기간에만 적용한다.** 하루 등록은 그날을 집어 고른 것이라 토요일을 골랐다면
  그 토요일이 맞다.
- **`CalendarGrid`는 26번이 재사용할 모양으로 뺐다.** 칸 장식은 `decorate(date) => {disabled,
  selected}` 틈으로 들어오고, 26번의 점·소멸 밑줄은 이 타입을 넓혀 받는다. 달력 계산은 전부
  `Temporal.PlainDate`/`PlainYearMonth` 속성이다(7.7절).
- **코드 리뷰(Standards/Spec 두 축)에서 세 가지를 고쳤다.** ① 기간 경로에서 종료일을
  시작일과 같은 날로 누르면 하루 등록으로 접는다 — 그러지 않으면 토요일을 집어 골랐는데
  주말 제외가 그 하루를 지워 0건이 된다("하루 등록에 주말 제외를 적용하지 않는다"는 원칙의
  구멍이었다). ② `pick-end`에 `[하루로]` 되돌아가는 문을 냈다 — 없으면 `[기간으로]`를 잘못
  누른 사람이 시트를 닫고 3클릭을 처음부터 다시 밟는다. ③ 메모를 조정 입력과 같게 trim해
  저장한다.
- **확인 방법**: `entry-dates` vitest 7건 + `pnpm verify` 전체 통과. 실제 화면은 vite 렌더러를
  `window.yeoncha` 스텁으로 브라우저에 띄워(임시 하네스, 검증 후 삭제) 눈으로 확인했다 —
  3클릭 하루 등록 후 헤더 14→13일 즉시 갱신, 8/21(금)~8/25(화) 기간이 주말 제외 기본 켜짐으로
  3건(끄면 5건), 반반차 0.25가 미래 날짜라 예정 0.25로 반영, 월 이동, 기존 기록일(8/14) 비활성,
  격자 폭 360px(≤380). 트레이 갱신은 커밋 → 상태 구독자 푸시라는 22번과 같은 통로다.
