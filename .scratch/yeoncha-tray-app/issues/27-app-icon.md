# 27. 앱 아이콘 제작

Type: task
Status: resolved
Blocked by: 13

## What to build

DMG · NSIS · 작업 표시줄 · Dock에 뜨는 **앱 아이콘**. **512px 원본 하나에서 `.icns`(macOS)와
`.ico`(Windows)를 뽑는다.**

**트레이 글리프와는 별개의 그림이다**([스펙 6절](../spec.md)). 하나에서 파생시킬 수 없는 것이
실측으로 확인됐다 — 달력은 512px에서 좋고 16px에서 고리 둘이 상단 띠에 먹혀 뜻을 잃으며, 대시는
16px에서 완벽하고 512px에서 「빼기 버튼」이 된다. **512px 앱 아이콘을 16px로 축소하면 파란
얼룩이 된다.**

**16px 아이콘 파일을 만들지 마라**(6.3절). 트레이에 들어가는 것은 파일이 아니라 15번의 런타임
canvas 렌더이고, 이 목록에 없다.

정해진 것은 **"시스템 블루 squircle + 흰 달력, 트레이 글리프와 별개"** 까지다. 획 두께·모서리
반경 같은 수치는 **결정이 아니라 제작**이므로 그림을 그릴 때 정한다.

## Acceptance criteria

- [x] 512px 원본 하나가 저장소에 있고, 거기서 `.icns`와 `.ico`를 만드는 경로가 문서화되어 있다
- [x] 아이콘이 시스템 블루 squircle + 흰 달력이다
- [x] `.ico`가 Windows가 쓰는 크기들을 담고 있고, `.icns`가 macOS가 쓰는 크기들을 담고 있다
- [x] **16px 전용 아이콘 파일을 만들지 않았다**
- [x] 트레이 글리프(15번)와 파일을 공유하지 않는다
- [x] Dock/작업 표시줄에서 눈으로 확인했다(Windows 결과는 코멘트에 기록한다)

## 구현 기록

**산출물은 `apps/desktop/build/`에 셋** — `icon-512.png`(원본) · `icon.icns` · `icon.ico`.
생성 경로는 `apps/desktop/scripts/make-app-icon.mjs` 하나이고 `build/README.md`가 재생성
방법을 적는다. 스크립트는 의존성 없이 512px을 렌더한 뒤 **그 비트맵을 축소해 모든 작은
크기를 파생한다**(크기별 별도 드로잉 없음). `.icns`는 iconutil(macOS 전용), `.ico`는
스크립트가 직접 인코딩한다(16–128 BMP + 256 PNG, Vista+ 규약).

제작에서 정한 수치: squircle은 초타원 지수 5·한 변 412px(macOS 아이콘 그리드 비율),
배경은 시스템 블루 세로 그라디언트(#339DFF→#0066E0), 달력은 본체 228×198(r30) + 고리 바
둘(26×74) + 파란 헤더 틈 + 날짜 칸 4×3(32×20). 전부 스크립트 상단 상수라 그림 수정은
상수 수정 → 재실행이다.

담긴 크기 — `.icns`: 16·32·64·128·256·512(512@2x=1024는 원본에서 **확대**가 되므로 뺐다),
`.ico`: 16·24·32·48·64·128·256. 16px은 두 컨테이너 안의 표준 엔트리로만 존재하고 별도
파일이 아니다. 트레이 글리프(`src/main/glyph.ts`)는 이 산출물을 전혀 참조하지 않는다.

### 확인한 방법

- 512px 원본과 128·32px 파생(icns 라운드트립 추출)을 이미지로 직접 확인 — squircle + 흰
  달력이 각 크기에서 읽힌다.
- `electron-builder --dir`로 언팩 패키징 → `CFBundleIconFile=icon.icns`, 번들 속 icns가
  원본과 sha 일치, **Finder 아이콘 뷰에서 macOS가 렌더한 아이콘을 눈으로 확인했다**
  (build/ 디렉터리는 electron-builder 기본 buildResources라 설정 없이 자동으로 집혔다).
- `.ico`는 독립 디코더 둘로 교차 확인 — macOS `sips`가 256px로 읽고, 별도 파서로 엔트리
  7개(BMP 6 + PNG 1)의 크기·형식을 확인했다.

## Comments

- **macOS에서 "Dock에서 확인"은 문자 그대로는 불가능하다** — 이 앱은 15번이
  `app.dock?.hide()`를 호출하는 트레이 상주 앱이라 실행 중 Dock에 항목이 없다. 아이콘이
  실제로 렌더되는 자리(Finder·DMG·Launchpad) 중 Finder에서 확인했고, 패키징된 앱이 실행되어
  트레이에 뜨는 것도 같은 세션에서 봤다. DMG 실물은 28번 첫 패키징에서 다시 보게 된다.
- **Windows는 미확인이다**(macOS 개발 기계). `.ico`의 구조·크기 검증까지만 했고, 탐색기·작업
  표시줄·NSIS 실물 확인은 Windows에서 처음 패키징하는 시점(28번 이후)에 해야 한다. 28번의
  `win.signExecutable: false`(리소스 편집 유지) 전제가 지켜져야 `.ico`가 exe에 붙는다.
- **16px 파생은 스펙 예측대로 파란 얼룩이다.** 컨테이너 표준 엔트리라 남겨뒀다 — 이 크기가
  쓰이는 자리는 Finder 리스트 뷰·탐색기 상세 뷰이지 트레이가 아니고, 트레이는 15번의 런타임
  대시가 맡는다.
