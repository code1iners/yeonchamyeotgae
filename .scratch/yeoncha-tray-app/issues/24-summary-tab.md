# 24. 요약 탭

Type: task
Status: resolved
Blocked by: 20, 22

## What to build

**"지금 몇 개인지"의 근거를 보여주는 화면.** 트레이 숫자가 왜 그 값인지가 전부 여기에 있다.

- **잔여는 헤더 한 줄에 작게.** 큰 숫자로 반복하지 않는 이유는 트레이에 이미 있기 때문이다.
  다만 **소수를 그대로 쓴다**(`12.25일`). **반올림·절사 금지** — Windows에서는 이 값이 정확한
  잔여를 볼 수 있는 유일한 화면이다([스펙 5.1절](../spec.md)).
- **`발생 / 사용 / 예정 / 잔여` 4줄 표.** 각 행 오른쪽에 무엇인지 한 줄로 적는다
  (`발생 18 — 지금 살아 있는 발생분`). 목적이 **회사 시스템 숫자와의 대조**이므로 숫자만 있으면
  무엇과 대조하는지 알 수 없다.
- **각주 한 줄이 유일한 해답이다.** 4줄의 `예정`에는 **배정된 몫만** 적고, 표 아래에
  `등록한 예정은 4일이지만 1일은 내년 발생분에서 나갑니다 — 올해 잔여에 없습니다`를 둔다.
  등록 총량을 쓰면 4줄이 검산되지 않고, 배정분만 쓰면 사용자가 등록한 4일째가 요약에서 사라진다.
- **살아 있는 발생분 리스트**를 소멸 임박 순으로. 각 행에 `남은 양/총량`과 소멸일. 소멸까지
  **60일 이내면 날짜 대신 `D-31`을 경고색으로**.
- **초과일 때**: 헤더 잔여를 경고색으로, 4줄 위에 `초과` 행 추가, 상단에 원인 한 줄과
  **`조정을 추가` 링크**. 이 링크는 설정 탭으로 점프하며 **조정 폼을 열어둔 채로** 넘긴다 —
  원인 표시와 조치가 한 동선이어야 한다.

이 탭이 **소멸을 알아채는 두 경로 중 하나**를 갖는다(5.7절). 트레이는 소멸에 아무 표시도 하지
않고 OS 알림도 없다.

`[휴가 등록]` 버튼 자리를 만든다. 시트 자체는 25번이다.

## Acceptance criteria

- [x] 헤더에 잔여가 소수 그대로 뜬다(`12.25일`). 반올림도 절사도 하지 않는다
- [x] `발생 / 사용 / 예정 / 잔여` 4줄이 있고 각 행에 한 줄 설명이 붙는다
- [x] 4줄이 산술적으로 검산된다 — `예정`에 **배정된 몫만** 들어간다
- [x] 미래 발생분에서 나가는 예정이 있으면 표 아래 각주 한 줄이 그 사실을 말한다(케이스 J로 확인)
- [x] 살아 있는 발생분이 소멸 임박 순으로 나오고 각 행에 `남은 양/총량`과 소멸일이 있다
- [x] 소멸까지 60일 이내인 행은 날짜 대신 `D-31` 형태의 배지가 경고색으로 뜬다
- [x] 초과일 때 헤더가 경고색이 되고 `초과` 행이 붙고 원인 한 줄과 `조정을 추가` 링크가 상단에 뜬다
- [x] `조정을 추가`를 누르면 설정 탭으로 이동하며 조정 폼이 열린 상태다
- [x] `[휴가 등록]` 버튼이 있다
- [x] 소멸 임박에 트레이는 아무 반응도 하지 않는다(4.4절)

## Answer

**이 탭이 하는 일은 잔여를 다시 말하는 것이 아니라 근거를 대는 것이다.** 잔여는 헤더 한 줄에
작게 두고(소수 그대로, 반올림도 절사도 없다), 본문은 4줄 표와 살아 있는 발생분 리스트다.

- **코어에 `livingGrants` 하나를 뒀다**(`packages/core/src/summary.ts`). 소멸까지 남은 날과
  임박 여부만 붙인다. **살아 있다는 판정 자체는 하지 않는다** — `computeBalance`가 이미 내는
  값을 쓴다. 그래서 `GrantDetail`에 `living`을 더했다(3.3절의 `발생일 <= 조회일 <= 소멸일`).
  **소멸하지 않은 것과 다르다**: 아직 오지 않은 발생분도 `expired`는 거짓이라, 소멸 여부만
  보면 케이스 J의 2026-01-01 발생분이 올해 리스트에 섞여 든다.
- **60일 경계와 D-0을 테스트가 고정한다**(`summary.test.ts`). 소멸일 당일이 `D-0`이고 아직
  살아 있다 — 그 날에는 쓸 수 있다(3.3절).
- **4줄의 검산을 테스트로 박았다**(`balance.test.ts`의 `요약 4줄의 검산`). 케이스 J·K·L과
  음수 조정에서 `발생 − 사용 − 예정 − 초과 = 잔여`가 성립한다. `예정`에 등록 총량을 쓰면
  이 항등식이 깨지고, 그때 4줄은 대조표가 아니라 그냥 숫자 넷이 된다.
- **각주가 두 갈래다.** 등록한 예정이 **전부** 미래 발생분에서 나가면
  `등록한 예정 3일은 전부…`로 적는다 — `3일이지만 3일은`이라고 쓰면 두 값이 다르다고
  말하는 문장이 스스로를 배반한다.
- **`조정을 추가`는 탭과 한 값으로 넘긴다**(`App.tsx`의 `Selection`). 처음에는 요청 횟수를
  따로 들고 `key`로 섹션을 다시 세웠는데, **설정 탭은 탭을 옮길 때마다 통째로 다시 서므로**
  횟수가 줄지 않아 그냥 설정 탭을 눌러 들어온 사람에게도 폼이 열렸다. 탭과 이유를 한 값으로
  묶으면 탭을 고르는 순간 이유가 함께 지워진다.

### 확인 방법

22·23번과 같은 임시 렌더러 하네스(실제 `App`을 브라우저에 올리고 셸 API만 가짜로 채운 것)로
확인했고 하네스는 확인 뒤 지웠다. 코어 테스트 116건은 `pnpm verify`가 돌린다.

| 케이스 | 화면 |
| --- | --- |
| J (조회일 2025-12-01) | 잔여 **5일**, 4줄 `15 / 10 / 0 / 5`, 각주 `등록한 예정 3일은 전부…`, 리스트 `연차 5/15 D-30` |
| G (2025-06-30) | 잔여 **18.5일**, `월차 1/1 D-0` 11줄 뒤 `연차 7.5/7.5 2025-12-31` — 소멸 임박 순 |
| K (2025-06-01) | 헤더 **−3일 경고색**, 원인 한 줄 + `조정을 추가`, 4줄 `15 / 15 / 0 / 초과 3 / −3` |
| K에서 `조정을 추가` | 설정 탭 + 조정 폼 열림, 발생일 `2025-06-01` · 소멸일 `2025-12-31` 기본값 |
| 그 뒤 요약 → 설정 탭 클릭 | **폼이 닫혀 있다** — 링크로 들어온 것과 그냥 들어온 것이 갈린다 |
| 폼에 `5 / 2025-01-01 / 2025-12-31` | 잔여 **2일**, 초과 행·경고색 사라짐, 리스트에 `조정 2/5` — **케이스 L** |
| 평시 | 헤더 `12.25일`, 4줄 `15 / 2.75 / 0 / 12.25` — 소수 그대로 |
| 온보딩 | 헤더 없음, 요약·이력 비활성 — 20번 그대로 |

## Comments

- **`초과` 행은 잔여 바로 위에 세웠다.** 티켓의 "4줄 위에"를 위치가 아니라 "그 4줄에 더해"로
  읽었다 — 검산이 위에서 아래로 읽히려면 빼는 항이 전부 잔여보다 앞에 있어야 한다.
  스펙 5.1절의 "그 위에"와도 어긋나지 않는다.
- **경고색 조건을 `초과 > 0` 하나로 뒀다.** 잠깐 헤더만 `잔여 < 0`으로 뒀다가 되돌렸다 —
  **두 조건이 실제로 갈리는 입력이 있다**(2025-03월 18일 사용 + 발생일 2025-06-01짜리 조정
  +5일, 조회일 2025-11-05 → `잔여 2 / 초과 3`). 그 상태에서 헤더만 평상색이면 본문의
  `초과 3` 행과 헤더가 다른 말을 한다. 대가는 **잔여가 양수인데 헤더가 경고색인 화면**이고,
  그때 트레이는 평범한 `2`를 띄운다. 살아 있는 초과가 남아 있다는 사실을 우선했다.
- **각주 문구가 스펙 예시와 다르다.** 스펙은 `내년 발생분 / 올해 잔여`라고 적지만 그 발생분이
  내년 것이라는 보장이 없어(회계연도 기준의 월차·비례분도 미래 발생분이 된다)
  `아직 생기지 않은 발생분 / 지금 잔여`로 적었다.
- **월차 11건은 11줄로 나온다.** 케이스 G에서 `월차 1/1 D-0`이 11번 반복된다. 실제로 11개의
  레코드이고 부분 사용이 시작되면 `0/1`과 `1/1`이 갈리므로 묶지 않았다. 팝오버 높이는
  내용에 따라 늘어난다(5.6절) — 이 케이스가 요약 탭의 최대 높이다.
- **`[휴가 등록]`은 `disabled`다.** 시트가 25번이라 눌러도 갈 곳이 없다. 25번이 `disabled`를
  떼고 시트를 연다.
- **셸에는 여전히 자동 테스트가 없다**(스펙 Testing Decisions). 위 표는 눈으로 확인한 것이고
  회귀를 잡아주지 않는다. `조정을 추가` 뒤 탭을 다시 눌렀을 때 폼이 열려 있던 버그가 정확히
  이 구멍에서 나왔다 — 코드 리뷰에서 잡았다.
- **테스트 시나리오 헬퍼를 `test-scenarios.ts`로 뺐다.** `balance.test.ts`와 `summary.test.ts`가
  같은 케이스 빌더를 쓴다. 코어의 공개 API(`index.ts`)로는 나가지 않는다.
