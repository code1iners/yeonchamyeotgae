# 20. 온보딩 — 탭 셸과 입사일 입력

Type: task
Status: resolved
Blocked by: 19

## What to build

앱을 처음 실행하면 **입사일을 넣는 화면이 바로 열리고**, 입사일과 기준방식을 저장하면 파일이
생기고 트레이 숫자가 그 자리에서 바뀐다. 팝오버의 탭 3개(요약 / 이력 / 설정) 골격이 이 티켓에서 선다.

`ui-design` Skill을 적용한다. 실제 메뉴바 앱(runcat, Itsycal, Stats)의 기성 패턴을 우선하고,
시각 언어는 **시스템 네이티브, 장식 없음, 강조색은 시스템 블루 하나**다([스펙 5절](../spec.md)).

- **입사일이 없으면 설정 탭만 활성이고 요약·이력은 비활성**이며 **조정 섹션도 감춘다** — 입사일도
  없는데 조정을 넣을 이유가 없다.
- 온보딩이 말해야 하는 것은 `입사일을 넣으면 연차를 계산합니다` **한 줄**이다.
- **온보딩 화면에 글리프를 넣지 않는다**(6절) — 방금 그 글리프를 눌러 들어왔다.
- 트레이의 대시를 누르면 **설정 탭이 열린다**(4.4절).
- **별도 창을 만들지 않는다.** 전부 팝오버 안이다.

요약·이력 탭의 내용은 뒤 티켓(24 / 26)이다. 이 티켓은 탭 전환과 활성/비활성 규칙까지다.

## Acceptance criteria

- [x] 첫 실행에서 팝오버가 설정 탭으로 열리고 입사일 입력이 바로 보인다
- [x] 입사일이 없는 동안 요약·이력 탭이 비활성이고 조정 섹션이 보이지 않는다
- [x] 입사일과 기준방식(입사일 기준 / 회계연도 기준)을 저장하면 `data.json`이 처음 생기고 트레이가 대시에서 숫자로 바뀐다
- [x] 세 탭이 전환되고 팝오버 높이가 탭 내용에 맞춰 달라진다(폭은 380px 고정)
- [x] 트레이 대시를 누르면 설정 탭이 열린다
- [x] 입사일을 바꾸면 계속근로연수가 리셋된 값으로 트레이가 갱신된다(이전 기록 삭제 여부를 묻는 것은 23번)
- [x] 별도 창이 없고, 렌더러가 도메인 규칙을 직접 계산하지 않는다(전부 코어의 결과를 받아 그린다)

## Answer

`apps/desktop/src/renderer/`에 탭 셸과 설정 탭을 세웠다. 검증은 실제 앱을 CDP로 눌러 본 실측이다.

- **파일** — `App.tsx`(헤더 · 탭 막대 · 탭 라우팅 · 높이 보고), `SettingsTab.tsx`(입사일 ·
  기준방식 · 저장), `use-app-state.ts`(셸 상태 구독), `styles.css`(07번 프로토타입 확정안 F의
  토큰과 밀도를 그대로 옮긴 것). `index.html`의 인라인 스타일은 `styles.css`로 옮겼다.
- **활성/비활성은 상태 하나에서 나온다** — `settings === null`이 곧 온보딩이고, 그 동안
  요약·이력 탭이 `disabled`이며 그릴 탭은 설정으로 고정된다. **그래서 트레이 대시 클릭에
  별도 IPC가 없다**(4.4절) — 대시가 뜨는 상태와 설정 탭만 열리는 상태가 같은 조건이다.
- **온보딩 문구는 한 줄이고 글리프는 없다**(6절) — `입사일을 넣으면 연차를 계산합니다.`
- **조정 섹션은 입사일이 있을 때만 그린다**(5.4절). 목록과 네 필드 폼은 22번이 채운다.
- **렌더러는 도메인 규칙을 계산하지 않는다.** 코어를 부르는 곳이 없고 `@yeoncha/core`에서
  가져오는 것은 `Settings` 타입뿐이다. 헤더의 잔여는 `state.balance.balance`를 **반올림도
  절사도 없이** 그대로 쓴다(5.1절 — Windows에서는 이 화면이 정확한 값의 유일한 자리다).
- **저장하면 커밋 하나로 끝난다** — `commit({ settings })` → 파일 생성 → 재계산 → 트레이 갱신
  → `STATE_CHANGED` 푸시. 렌더러는 커밋의 반환값을 쓰지 않고 푸시만 받는다(경로가 하나다).
- **온보딩을 끝내도 화면이 튀지 않는다.** 처음 구현은 저장한 순간 요약 탭으로 넘어갔다 —
  탭이 열리면서 기본값(`summary`)이 드러났기 때문이다. 온보딩 동안 고른 탭도 설정으로
  맞춰 두는 것으로 고쳤고 실측으로 확인했다.
- **셸이 민 상태가 입력 중인 값을 되돌리지 않는다.** 저장값이 실제로 달라졌을 때만 폼을
  다시 채운다 — 자정·절전 복귀 푸시(21번)가 타이핑 중에 와도 입력이 살아남는다.

### 실측 (Electron 44, macOS, CDP로 메인·렌더러 양쪽에 붙어 확인)

메인 프로세스에서 `Tray.prototype`의 `setTitle`/`setImage`/`setToolTip`을 감싸 호출을 기록하고,
렌더러에서 실제로 값을 넣고 버튼을 눌렀다.

| 단계 | 확인한 것 |
| --- | --- |
| 첫 실행(파일 없음) | **팝오버가 스스로 열린다**(`visible: true`). 트레이 `image 16x16` + `title ""` + 툴팁 `입사일을 입력하세요`. 380×188, 헤더 없음, 설정 탭 선택, 요약·이력 `disabled: true`, 조정 섹션 없음(`.sec-title` 0개) |
| 트레이 대시 클릭 | 한 번 눌러 닫히고(`visible: false`) 다시 눌러 열린다 — 열리는 것은 설정 탭이다 |
| 입사일 2024-01-15 · 회계연도 저장 | `data.json`이 처음 생기고(2칸 들여쓰기), 트레이가 `title ""` → **`title "15"`**, 툴팁 `잔여 15일`. 요약·이력 `disabled: false`, 조정 섹션 등장, 탭은 설정 그대로 |
| 탭 전환 | 요약 112px / 이력 112px / 설정 248px — **창 높이가 따라가고 폭은 세 탭 모두 380** |
| 깨진 `data.json` | 온보딩 문구 대신 `저장 파일을 읽지 못했습니다.`가 뜨고, 저장을 누르면 `저장하지 못했습니다 — 읽지 못한 저장 파일에는 쓰지 않는다`가 붙으며 **파일 md5가 변하지 않는다** |
| 입사일 2025-06-01로 변경 | 트레이 `15` → **`8.75`**, 툴팁 `잔여 8.75일`, 파일의 `hireDate`가 바뀐다(이전 기록 삭제 여부는 23번) |
| 라이트/다크 | `prefers-color-scheme`를 양쪽으로 두고 캡처해 대비를 확인했다 |

`pnpm verify`(코어 테스트 90건)와 `pnpm build` 통과.

## Comments

- **셸에는 자동 테스트를 두지 않았다**(스펙 Testing Decisions — seam은 계산·표시·직렬화 셋이고
  전부 코어에 있다). 이 티켓이 만든 것은 렌더러 UI라 그 셋에 앉지 않으므로 위 실측을 남겼다.
- **헤더의 잔여를 이 티켓에서 세웠다.** 24번 AC가 헤더 잔여를 요구하지만 헤더는 탭 밖에
  있는 셸 가구라 여기서 자리를 잡는 편이 자연스러웠다. **경고색·`초과` 행·각주는 24번**이다.
  온보딩 동안에는 헤더 자체를 그리지 않는다(아래 리뷰 반영).
- **읽기 실패에서 팝오버 전체를 차지하는 오류 화면은 23번**이다(5.5절). 이 티켓은 그 상태에서
  화면이 **거짓말하지 않는 데까지만** 한다 — 온보딩 문구 대신 사실 한 줄을 띄우고, 저장은
  셸이 준 사유를 그대로 옮긴다.
- **요약·이력 탭은 `이 탭은 아직 비어 있습니다.` 한 줄이다.** 24·26번이 채운다.
- 조정 섹션은 지금 제목과 빈 상태 한 줄뿐이라 사용자가 넣을 수 있는 것이 없다 — 22번이
  붙기 전까지의 중간 상태다.

### 코드 리뷰 반영 (2026-08-27)

`/code-review` 두 축이 지적한 것 중 고친 것:

- **(Spec, 실질 결함)** **첫 실행에서 팝오버가 열리지 않았다.** `app.whenReady()`에 `showPopover()`가
  없어 사용자가 메뉴 막대의 대시를 **찾아서 눌러야** 온보딩에 닿았다 — 유저 스토리 1번이
  없애려던 바로 그 비용이다. 입사일 미설정일 때만 트레이 위치에 붙여 스스로 연다.
  읽기 실패에서는 열지 않는다(그 화면은 23번이다).
- **(Spec)** **온보딩에 헤더를 두지 않는다.** 잔여 자리의 `—`는 방금 눌러 들어온 트레이
  글리프와 같은 것이고(6절), 이 화면이 말할 것은 한 줄뿐이다(5.4절).
- **(Spec)** **저장 실패 문구가 원인을 단정했다.** `commit`은 쓰기 차단 외에 쓰기 자체
  (`serialize`/`parse` 재검증, fs 오류)에서도 던지는데 전부 "읽지 못했습니다"로 띄웠다 →
  셸이 준 사유를 그대로 옮긴다(Electron이 붙이는 채널 접두만 걷어낸다).
- **(Spec)** **읽기 실패가 온보딩 문구로 새어 나갔다** — `settings === null`이 "파일 없음"과
  "못 읽음" 양쪽에서 같기 때문이다. 렌더러가 이미 받는 `AppState.read`로 갈라 사실 한 줄을 띄운다.
- **(Standards)** `comment-style`의 "상수 항목에도 주석"을 `TABS`·`GRANT_BASIS_OPTIONS`에서 빠뜨렸다 → 채웠다.
- **(Standards)** `color: #fff` 리터럴 두 곳 → `--on-accent` 토큰 하나. 미사용 토큰 `--fg-3` 제거.
- **(Standards, 스멜)** `formatBalance`가 `AppState` 전체를 받아 `balance.balance`만 썼다(Feature Envy)
  → `Balance | null`로 좁혔다.
- **(Standards, 스멜)** 설정 비교를 `` `${hireDate}\n${grantBasis}` `` 문자열로 인코딩했다
  (Primitive Obsession) → 필드를 직접 비교하는 `isSameSettings` 하나로.
- **(Standards)** `getState()`에 `catch`가 없어 조용한 unhandled rejection이 됐다 → 붙였다.

고치지 않은 것:

- **탭을 하나 더할 때 `TABS`와 렌더 캐스케이드 두 자리를 고쳐야 한다**(Shotgun Surgery 맹아).
  `TABS` 항목에 렌더 함수를 달면 한 곳으로 모이지만, 탭은 셋으로 확정이고(5절) 24·26번이
  내용을 채우면서 각 탭이 받을 props가 갈릴 자리라 그때 판단하는 편이 낫다.
- **버튼 `border-radius: 6px`은 `ui-design` Skill의 8~10px과 다르다.** 07번이 확정한 메뉴바 앱
  (Itsycal·Stats)의 밀도를 따른 값이고 근거를 `styles.css` 상단에 적었다 — Skill 절차 3의
  "차이를 알린다"에 해당해 여기 남긴다.
