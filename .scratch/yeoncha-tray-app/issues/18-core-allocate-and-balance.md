# 18. 배정과 잔여 (allocate / computeBalance)

Type: task
Status: ready-for-agent
Blocked by: 17

## What to build

휴가 기록을 발생 레코드에 **배정**하고 조회일의 **잔여**와 내역을 내는 순수 함수 둘. 이 티켓이
닫히면 **제품의 전부가 계산 가능해진다** — [검증 케이스 14건](../spec.md)의 잔여 열 전부가 여기서 나온다.

**잔여는 합계끼리의 뺄셈이 아니다**([스펙 3.1절](../spec.md)). 뺄셈으로 구현하면 소멸일이 다른
발생분이 겹칠 때 같은 입력에 잔여가 둘 나오고, 과거 휴가 기록이 누적되어 매년 1월에 이중
차감이 난다. **배정 결과는 저장하지 않고 조회 시점에 매번 계산한다.**

**계산 엔진은 잔여 숫자 하나를 반환하지 않는다**(1절). 발생 레코드마다
`발생일 / source / 일수 / 배정된 사용량 / 남은 양 / 소멸일 / 소멸 여부`를 담은 내역과, 여기에
**초과 일수**와 **미래 발생분에 배정된 예정**을 얹어 돌려준다 — 트레이용·팝오버용으로 나눠
부르면 같은 일을 두 번 한다.

배정 규칙(3.4절)과 잔여 공식(3.5절), 초과의 수명(3.6절)이 이 티켓의 본문이다. 특히
**초과 일수는 그 휴가 날짜에 유효했던 발생 레코드들의 소멸일 중 가장 늦은 것까지 살아 있다가
사라진다** — 수명을 주지 않고 영구히 빼면 3.1절의 누적 오차가 그대로 돌아온다.

## Acceptance criteria

- [ ] 휴가 기록을 **날짜 오름차순**으로 처리하고, 각 기록을 그 **휴가 날짜에 유효한 양수 발생 레코드**에 배정한다
- [ ] 후보가 여럿이면 **소멸 임박 순**으로 채운다. 정렬 키는 `소멸일 ↑ → 발생일 ↑ → source(monthly → annual → adjustment) → 입력 순서`
- [ ] 한 기록이 여러 레코드에 **쪼개져 배정된다**(0.25 단위)
- [ ] 배정할 잔량이 모자라면 남은 일수가 **초과**로 간다
- [ ] 유효 조건이 `발생일 <= 대상일 <= expiryDate`다 — **소멸일에도 아직 쓸 수 있다**(3.3절)
- [ ] 소멸분은 애초에 "발생"에 들어가지 않는다(공식이 3항으로 유지된다)
- [ ] **음수 조정은 배정 대상이 아니라 합산 항**이고, 소멸일이 지나면 음수 레코드도 사라진다
- [ ] 초과의 수명이 3.6절 그대로다. 그 날짜에 유효한 레코드가 하나도 없었다면(발생 전 사용) 그 뒤 처음 생기는 발생분의 소멸일을 쓴다
- [ ] 케이스 A(3) · B(11) · C(15) · D(16) · E(25, 2046-01-01도 25)
- [ ] 케이스 G: 2025-06-30에 **18.5**, 2025-07-01에 **7.5**
- [ ] 케이스 H: 2025-03-10~03-14 5건 추가 후 2025-07-01에 **7.5** (소멸 늦은 순이면 2.5가 되어 5일 손해다 — 이 차이가 배정 규칙의 근거다)
- [ ] 케이스 I: 2026-01-05에 **15**, 2027-01-05에 **15** (단순 뺄셈이면 5와 −7)
- [ ] 케이스 J: 2026-02-10~02-12 예정 3일이 2026-01-01 발생분에 배정되고 2025-12-01 잔여가 **5**다. 미래 발생분에 배정된 예정이 결과에 실려 나온다(5.1절 각주가 이 값을 쓴다)
- [ ] 케이스 K: 2025-06-01에 **−3**, 2026-01-05에 **15**(2025년분이 소멸하며 초과 3일도 함께 사라진다)
- [ ] 케이스 L: 조정 `2025-01-01 / 2025-12-31 / +5`를 넣으면 2025-11-05 잔여가 **2**다. 소멸일만 2026-12-31로 늘리면 2026-01-05 잔여가 **17**이다(발생일이 입력일로 고정됐다면 20이 되어 초과 3일이 공짜로 생긴다)
- [ ] 케이스 M: 2024-02-28에 **0**, 2024-02-29에 **1**
- [ ] 케이스 N: 2025-01-10에 **24.75**, 2025-01-15에 **13.75**
- [ ] 내역이 결정론적으로 정렬되어 나온다(정렬 키의 뒤쪽 키가 하는 일이 이것이다)
