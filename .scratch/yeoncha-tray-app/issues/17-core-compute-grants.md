# 17. 발생 레코드 생성 (computeGrants)

Type: task
Status: resolved
Blocked by: 13

## What to build

`입사일 · 기준방식 · 조정 · (경계 산정용) 휴가 기록`을 받아 **발생 레코드 목록**을 내는 순수
함수. 배정과 잔여는 다음 티켓(18번)이고, 이 티켓은 **어떤 발생분이 언제 몇 개 생기고 언제
소멸하는가**만 고정한다.

규칙은 [스펙 3.2절](../spec.md)에 표 둘로 있다. 그대로 옮긴다.

- **월/년 더하기는 월말 클램프**를 쓴다(2024-01-31 + 1개월 = 2024-02-29). `Temporal.PlainDate.add()`의
  기본 동작(`constrain`)과 같아 **예외 코드가 필요 없다.**
- **일수가 아니라 날짜 산술**로 쓴다(`+1년 −1일`). "365일차/366일차"로 쓰면 윤년에서 어긋난다.
- **"오늘"은 인자다.** 코어가 내부에서 현재 날짜를 읽으면 안 된다(1절 제약).
- 미래 발생분은 **`max(조회일, 가장 늦은 휴가 기록 날짜)`까지** 생성한다 — 미래 **예정**이 미래
  발생분에 배정되어야 하기 때문이다. 경계가 데이터에서 나오므로 설정값이 늘지 않는다.
- 회계연도 개시일은 **1/1 고정**이고, 가산휴가의 근속연수는 **입사일에서만** 나온다(회계연도
  순번을 세지 않는다). 그래서 일수 공식 하나를 두 기준방식이 공유하고 회계연도 쪽은
  **발생일만 1/1로 옮긴 것**이 된다.
- **퇴사일 개념은 없다.**

## Acceptance criteria

- [x] `computeGrants`가 각 레코드에 `발생일 / source / 일수 / 소멸일`을 담아 돌려준다. `source`는 `'monthly' | 'annual' | 'adjustment'`
- [x] 입사일 기준: 월차 11건이 `입사일 + n개월`(n=1..11)에 각 1일씩, 소멸일은 11건 전부 `입사일 + 1년 − 1일`
- [x] 입사일 기준: 연차가 `입사일 + k년`에 `min(25, 15 + floor((k − 1) / 2))`일, 소멸일은 `발생일 + 1년 − 1일`
- [x] 회계연도 기준: 월차는 입사일 기준과 **동일**(법정이므로 회계연도와 무관), 소멸일은 `입사일 + 1년 − 1일`
- [x] 회계연도 기준: 첫 비례분이 입사 후 첫 1/1에 `15 × m / 12`(m = **완성 개월 수**), 소멸일은 그 해 12/31. m = 0이면 레코드를 만들지 않는다
- [x] 회계연도 기준: 연차가 매년 1/1에 발생하고 일수의 k는 **그 1/1 시점의 입사일 기준 완성 근속연수**다
- [x] 조정 레코드가 `source: 'adjustment'`로 목록에 **덧붙는다**(계산 결과를 덮어쓰지 않는다). 음수 일수도 그대로 실린다
- [x] 케이스 A~E의 발생 목록이 표와 일치한다 (2024-01-01 입사·입사일 기준: 2024-12-31에 월차 11건, 2025-01-01에 연차 15일, 2027-01-01에 16일, 2045-01-01에 25일이며 2046-01-01도 25)
- [x] 케이스 G의 발생 표가 일치한다 (2024-07-01 입사·회계연도: 월차 11건 2024-08-01~2025-06-01 소멸 전부 2025-06-30 / 비례분 2025-01-01에 **7.5** / 연차 2026-01-01에 15)
- [x] 케이스 M이 일치한다 (2024-01-31 입사: 월차 발생일 2024-02-29 → 03-31 → 04-30 → 05-31, 소멸일 전부 **2025-01-30**, 연차 발생일 **2025-01-31** — 경계가 하루도 벌어지지 않는다)
- [x] 케이스 N이 일치한다 (2024-01-15 입사·회계연도: 월차 11건 소멸 2025-01-14와 비례분 `15 × 11/12 = 13.75`가 2주간 겹친다)
- [x] **입사일 기준에서 두 종류가 겹치는 구간이 없다** — 누적 발생량 26일이 동시에 유효한 순간이 존재하지 않는 것을 테스트가 고정한다
- [x] `temporal-polyfill`의 명명 import를 쓰고 날짜 산술에 예외 분기가 없다

## Answer

[grants.ts](../../../packages/core/src/grants.ts) + 표 기반 테스트 12건으로 구현했다.
코어 테스트 49건(발생 12 + 직렬화 25 + 표시 4 + Temporal 8), `turbo run lint typecheck test` 전체 통과.

- **시그니처** — `computeGrants({ settings, entries, adjustments, today }): Grant[]`.
  `Grant`는 `grantDate / source / days / expiryDate`이고 날짜는 저장 경계와 같은
  YYYY-MM-DD 문자열이다. 비례분의 `source`는 `'annual'`이다 — 티켓이 source를
  세 값으로 고정했고 비례분은 회계연도 연차의 첫해 꼴이기 때문이다.
- **경계(horizon)** — `max(조회일, 가장 늦은 휴가 기록 날짜)`를 안에서 구하고, 발생일이
  경계와 같으면 포함(`compare > 0`일 때만 중단)이다. 미래 예정이 경계를 늘려 미래
  연차가 생성되는 것을 테스트가 고정한다.
- **일수 공식 하나를 두 기준방식이 공유한다** — `annualDays(k) = min(25, 15 + floor((k−1)/2))`.
  회계연도 쪽은 발생일만 1/1로 옮기고 k를 `completedYearsAt`(입사일 기준 완성
  근속연수)으로 구한다 — 회계연도 순번을 세지 않는 것을 테스트(2024-07-01 입사의
  2027-01-01 = 15일)가 고정한다.
- **완성 개월 수는 월차와 같은 셈법** — `completedMonthsAt`이 `입사일 + (m+1)개월 <= 1/1`
  판정이다. 12/31에 끝나는 달은 발생 경계가 1/1에 떨어지므로 경계에 1/1을 포함해야
  케이스 G의 m=6이 나온다. **1/1 입사는 첫 1/1의 k가 1이라 비례분 분기에 아예 닿지
  않는다** — 비례분+연차 이중 발생이 구조적으로 불가능하고 전용 테스트가 있다.
- **겹침 없음 불변식** — 입사일 3종(1/1·1/31·6/15)의 첫 2년 전 날짜를 훑어 유효 발생
  합이 26에 닿지 않는 것을 테스트로 고정했다.
- **월말 클램프** — `Temporal.PlainDate.add()` 기본 동작에 그대로 기대 예외 분기 0줄.
  케이스 M(2024-01-31 입사: 02-29 → … 소멸 2025-01-30, 연차 2025-01-31)이 표로 있다.
- **조정** — 계산 결과 뒤에 입력 순서대로 덧붙고 음수도 그대로 실린다. 경계 밖 날짜의
  조정도 실린다 — 배정이 "휴가 날짜에 유효한 레코드"만 보므로 걸러낼 이유가 없다.
- 코드 리뷰 반영: Spec 축 결함 0건, Standards 축에서 주석 2건(`monthlyExpiry` 선언
  주석 누락, 완성 개월 수 경계 설명)을 고쳤다. 중복 while 루프(`completedYearsAt`/
  `completedMonthsAt`) 추출은 도메인 의미 주석이 갈라져 있어 보류 — 세 번째 단위가
  생기면 추출한다.
