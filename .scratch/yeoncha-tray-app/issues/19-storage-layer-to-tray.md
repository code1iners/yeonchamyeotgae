# 19. 저장 계층 — 파일에서 트레이 숫자까지

Type: task
Status: resolved
Blocked by: 15, 16, 18

## What to build

셸이 저장 파일을 읽어 코어에 넘기고, 나온 잔여가 **트레이 숫자로 뜨는** 경로. 아직 UI는 없다 —
손으로 만든 `data.json`이 트레이 숫자를 바꾸는 것이 이 티켓의 데모다.

- **위치는 `app.getPath('userData')` 고정**이다. 경로를 설정값으로 열지 않는다([스펙 2절](../spec.md)).
- **쓰기는 변경마다 즉시, 원자적으로** — 임시 파일 → `fsync` → `rename`. **디바운스하지 않는다.**
- **백업(`data.json.bak`)은 파괴적 조작 직전에만** 남긴다. 그 조작은 둘뿐이다(입사일 변경에 따른
  기록 삭제, 가져오기 교체) — 둘 다 뒤 티켓이지만 백업을 남기는 함수는 여기서 만든다.
- **읽지 못한 파일에는 쓰지 않는다.** 이 규칙 하나가 읽기 실패 처리 전부를 결정한다. 오류
  **화면**은 23번이고, 이 티켓은 **상태와 쓰기 차단**까지다.
- **첫 실행에 파일을 만들지 않는다.** 파일 없음 = 입사일 없음이며, 그래서 코어에서 `hireDate`는
  언제나 날짜다(`string | null`이 아니다).
- "오늘"은 셸이 `Temporal.Now.plainDateISO('Asia/Seoul')`로 만들어 넘긴다(7.3절). **설정값으로 빼지 않는다.**
- 트레이 예산은 셸의 상수 둘이다 — macOS `Infinity`, Windows `3`(4.3절).

## Acceptance criteria

- [x] 파일이 없으면 앱이 파일을 만들지 않고 입사일 미설정 상태로 뜬다(트레이는 15번의 대시)
- [x] 손으로 유효한 `data.json`을 넣고 앱을 켜면 트레이에 잔여가 뜬다 — macOS는 `12.75`, Windows는 `12`
- [x] **툴팁이 양쪽 다 정확한 값을 갖는다** — `연차몇개 — 잔여 12.75일`. 입사일 미설정이면 `연차몇개 — 입사일을 입력하세요`
- [x] 쓰기가 임시 파일 → `fsync` → `rename`이고, 쓰기 중 강제 종료해도 원본이 반쯤 덮여 있지 않다
- [x] `invalid-json` / `schema-mismatch` 상태에서 **파일에 쓰지 않는다**(사용자가 고를 때까지)
- [x] `future-version` 상태에서 읽기·쓰기 모두 중단되고 백업 복구 경로를 제안하지 않는다 — 그 백업도 신버전이 남긴 것이다
- [x] 파괴적 조작 직전에 `data.json.bak`을 남기는 함수가 있고 그 두 자리(입사일 변경 삭제 / 가져오기)에서만 불린다 — 그 두 자리가 모두 23번이라 **지금은 호출자가 0**이다
- [x] 코어에 넘기는 "오늘"이 `Asia/Seoul` 고정이고 셸의 한 곳에서만 만들어진다
- [x] 트레이 예산이 셸의 상수 둘이며 플랫폼 지식이 그 둘로 끝난다 — 셸에 `if (isMac)` 포매팅 분기가 없다
- [x] preload가 렌더러에 노출하는 IPC 계약이 정의되어 있다(읽기 상태 · 잔여와 내역 · 변경 커밋)

## Answer

`apps/desktop/src/{shared/ipc,main/{atomic-write,data-file,store,data-ipc,tray-number,tray,index},preload/index}.ts`로
구현했다. 검증은 전부 실측이다(실행 로그는 아래).

- **모듈 경계** — `atomic-write`(파일 시스템 지식) → `data-file`(저장 파일 지식: 경로·판정·백업)
  → `store`(셸 상태·"오늘"·쓰기 차단·커밋) → `data-ipc`/`tray`(표면). 코어는 `parse`/`computeGrants`/
  `computeBalance`/`formatTrayLabel`만 부르고 셸은 도메인 규칙을 만들지 않는다.
- **원자적 쓰기** — `writeFileAtomic(path, text)`: 임시 파일 → `fsync` → `rename`. 500MB를 쓰는
  자식 프로세스를 쓰기 시작 직후 `SIGKILL`로 죽여 **원본 35바이트가 그대로 남고 반쯤 쓰인 쪽은
  `data.json.tmp`뿐**인 것을 실측했다. 디렉터리 `fsync`는 하지 않는다(근거는 코드 주석).
- **읽기 상태 넷** — `missing` / `ok` / `error(invalid-json)` / `error(schema-mismatch)` /
  `error(future-version)`을 각각 손으로 만든 파일로 띄워 확인했다. 오류 셋 모두에서
  **커밋이 거부되고 파일의 md5가 변하지 않았다**. `future-version`도 같은 차단을 타며,
  갈래를 `ReadState`에 그대로 실어 23번이 "복구 버튼을 띄우지 않는" 분기를 할 수 있게 했다.
- **트레이 숫자** — 손으로 만든 `data.json`(2024-01-15 입사·회계연도, 2026년 기록 2.25일)로
  잔여 `12.75`가 나오고 `tray.getTitle()`이 실제로 `"12.75"`인 것, 툴팁이
  `연차몇개 — 잔여 12.75일`인 것을 읽어 확인했다. 같은 잔여에 Windows 예산(`maxGlyphs: 3`)을
  넣으면 `12`가 나온다. 파일이 없거나 읽기가 실패하면 대시 + `연차몇개 — 입사일을 입력하세요`다.
- **Windows 숫자 이미지** — 메인 프로세스에는 canvas가 없으므로 숨은 `BrowserWindow` 하나를
  빌려 그린다(4.1절의 canvas 경로). macOS에서 그 경로를 강제로 태워 16×16 비트맵을 덤프해
  `12` / `-25` / `0`이 정사각 안에 들어가는 것을 확인했다. 실물 Windows 확인은 못 했다(Comments).
- **예산은 상수 둘** — `MAC_MAX_GLYPHS = Infinity`, `WINDOWS_MAX_GLYPHS = 3`. 셸에 포매팅 분기가
  없고 `if (isMac)`은 **렌더링**(네이티브 텍스트 대 정사각 이미지)에만 남는다.
- **"오늘"은 `store.todayInSeoul()` 한 곳** — `Temporal.Now.plainDateISO('Asia/Seoul')`. 잔여를
  캐시하지 않고 `getState()`가 부를 때마다 다시 내므로 자정을 넘긴 값이 남을 자리가 없다.
  `temporal-polyfill`을 셸의 `devDependencies`에 넣었다(8.4절 — 셸의 런타임 `dependencies`는 계속 비어 있다).
- **IPC 계약** — `getState()` / `commit(change)` / `onStateChanged(listener)` / `reportContentHeight()`.
  팝오버 렌더러에서 `window.yeoncha.getState()`로 상태를 받고, `commit`으로 휴가 기록을 더해
  **파일 · 메인 상태 · 푸시 · 트레이 제목이 한 번에 12.75 → 12.25로 바뀌는 것**을 실측했다.
- **백업** — `backupDataFile()`이 원문을 그대로 복사(바이트 동일 실측)한다. **호출자는 아직 없다** —
  부를 자리 둘(입사일 변경 삭제 / 가져오기 교체)이 전부 23번이고, 그 밖에서 부르면 백업이
  "직전 상태"를 가리키지 않게 된다는 것을 함수 주석에 못 박았다. **읽지 못하는 원본은
  백업하지 않고 던진다** — 깨진 원본이 정상 `.bak`을 덮으면 23번의 `[백업에서 복구]`가
  돌아갈 곳을 잃는다(깨진 파일로 실행해 거부와 `.bak` 무변경을 실측).
- `pnpm verify`(코어 테스트 90건 포함)와 `pnpm build` 통과. 프로덕션 번들에서 숨은 렌더러로
  보내는 함수 원문이 살아 있는 것도 `out/main/index.js`에서 확인했다.

## Comments

- **셸에는 자동 테스트를 두지 않았다**(스펙 Testing Decisions — 테스트는 코어만, seam은 셋).
  이 티켓이 새로 만든 것은 전부 I/O·트레이·IPC라 그 셋에 앉지 않는다. 대신 위 실측을 남겼고,
  원자적 쓰기만은 `atomic-write.ts`를 electron에 의존하지 않는 모듈로 떼어 Node로 직접
  강제 종료 실험을 돌릴 수 있게 했다.
- **읽기 실패의 네 번째 갈래(I/O 오류)를 스펙 표에 없는 채로 다뤘다.** `ENOENT`가 아닌 읽기
  실패(권한 등)를 `invalid-json`으로 분류한다 — 처리(쓰기 차단 + 복구 경로 제안)가 같고,
  부팅 중에 예외로 죽는 것보다 낫다. 23번이 오류 화면 문구를 정할 때 다시 볼 수 있다.
- **오류 상태의 툴팁은 셋째 문구다** — `연차몇개 — 저장 파일을 읽지 못했습니다`. 처음에는
  스펙 4절이 정의한 둘뿐이라 셋째를 지어내지 않고 `입사일을 입력하세요`를 띄웠는데, 코드
  리뷰가 그것을 "툴팁은 양쪽 다 정확한 값을 갖는다"(4절) 위반으로 지적했다 — 입사일은 있고
  파일이 깨진 것이므로 사실이 아니다. 그래서 트레이가 받는 것을 `잔여 | 미설정 | 읽기 실패`
  세 갈래(`TrayView`)로 갈랐다. 글리프는 셋 중 둘에서 같은 대시다("숫자가 들어갈 자리인데
  아직 계산할 수 없다"가 양쪽 다 맞다). **무엇이 잘못됐고 무엇을 고를 수 있는지는 눌러서
  열리는 오류 화면(23번)이 말한다** — 툴팁은 거짓말만 하지 않으면 된다.
- **macOS에서 숫자를 띄울 때 트레이 이미지는 빈 이미지다**(`nativeImage.createEmpty()`).
  `setTitle`이 실제로 값을 갖는 것은 `getTitle()`로 확인했지만, **메뉴 막대에서 숫자 왼쪽에
  빈 자리가 남지 않는지는 눈으로 확인하지 못했다** — 15번 Comments의 그 제약(이 기기의 메뉴
  막대가 노치로 오버플로돼 새 상태 항목이 렌더되지 않는다)이 그대로다.
- **Windows 실물 확인: 미실시(보류).** 숨은 렌더러 → canvas → `nativeImage` 경로는 macOS에서
  픽셀 덤프로 확인했지만, 알림 영역에서 `SM_CXSMICON`과 크기가 맞는지·16px에서 두 글자가
  읽히는지는 Windows 기기에서 봐야 한다. 글자 크기는 폭과 잉크 높이(정사각의 0.72) 중 먼저
  막히는 쪽에 맞춘다 — 4.1절 실측표(16px 두 글자 cap 9.0)와 같은 자리에 오도록 잡은 값이다.
- **쓰기 직전에 파서를 태운다.** 처음에는 "타입이 계약"이라며 넣지 않았는데, 코드 리뷰가
  타입이 막지 못하는 구조 위반 하나를 찾아냈다 — `entries`의 **중복 `date`**(하루 1건
  불변식)다. 그대로 쓰면 저장은 성공하고 **다음 부팅에서 `schema-mismatch`로 쓰기가 영구
  차단된다**(2절이 경계한 "앱이 자기가 쓴 파일을 못 읽는다"가 그대로 실현된다). 이제
  `writeDataFile`이 `serialize` 결과를 `parse`에 태우고, 렌더러에서 중복 `date`를 커밋하면
  `ParseError: entries에 중복 date …가 있다`로 거부되며 파일이 변하지 않는 것을 실측했다.
  도메인 이상치는 여전히 통과시킨다 — 파서가 그렇게 만들어져 있다.
- 개발 중 `userData`는 `~/Library/Application Support/@yeoncha/desktop/`이다(패키징하면
  `productName`인 `연차몇개`가 된다). 실측에 쓴 `data.json`을 그 자리에 남겨 뒀다 —
  지우면 다시 입사일 미설정(대시) 상태로 뜬다.
