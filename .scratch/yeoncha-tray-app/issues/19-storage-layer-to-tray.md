# 19. 저장 계층 — 파일에서 트레이 숫자까지

Type: task
Status: ready-for-agent
Blocked by: 15, 16, 18

## What to build

셸이 저장 파일을 읽어 코어에 넘기고, 나온 잔여가 **트레이 숫자로 뜨는** 경로. 아직 UI는 없다 —
손으로 만든 `data.json`이 트레이 숫자를 바꾸는 것이 이 티켓의 데모다.

- **위치는 `app.getPath('userData')` 고정**이다. 경로를 설정값으로 열지 않는다([스펙 2절](../spec.md)).
- **쓰기는 변경마다 즉시, 원자적으로** — 임시 파일 → `fsync` → `rename`. **디바운스하지 않는다.**
- **백업(`data.json.bak`)은 파괴적 조작 직전에만** 남긴다. 그 조작은 둘뿐이다(입사일 변경에 따른
  기록 삭제, 가져오기 교체) — 둘 다 뒤 티켓이지만 백업을 남기는 함수는 여기서 만든다.
- **읽지 못한 파일에는 쓰지 않는다.** 이 규칙 하나가 읽기 실패 처리 전부를 결정한다. 오류
  **화면**은 23번이고, 이 티켓은 **상태와 쓰기 차단**까지다.
- **첫 실행에 파일을 만들지 않는다.** 파일 없음 = 입사일 없음이며, 그래서 코어에서 `hireDate`는
  언제나 날짜다(`string | null`이 아니다).
- "오늘"은 셸이 `Temporal.Now.plainDateISO('Asia/Seoul')`로 만들어 넘긴다(7.3절). **설정값으로 빼지 않는다.**
- 트레이 예산은 셸의 상수 둘이다 — macOS `Infinity`, Windows `3`(4.3절).

## Acceptance criteria

- [ ] 파일이 없으면 앱이 파일을 만들지 않고 입사일 미설정 상태로 뜬다(트레이는 15번의 대시)
- [ ] 손으로 유효한 `data.json`을 넣고 앱을 켜면 트레이에 잔여가 뜬다 — macOS는 `12.75`, Windows는 `12`
- [ ] **툴팁이 양쪽 다 정확한 값을 갖는다** — `연차몇개 — 잔여 12.75일`. 입사일 미설정이면 `연차몇개 — 입사일을 입력하세요`
- [ ] 쓰기가 임시 파일 → `fsync` → `rename`이고, 쓰기 중 강제 종료해도 원본이 반쯤 덮여 있지 않다
- [ ] `invalid-json` / `schema-mismatch` 상태에서 **파일에 쓰지 않는다**(사용자가 고를 때까지)
- [ ] `future-version` 상태에서 읽기·쓰기 모두 중단되고 백업 복구 경로를 제안하지 않는다 — 그 백업도 신버전이 남긴 것이다
- [ ] 파괴적 조작 직전에 `data.json.bak`을 남기는 함수가 있고 그 두 자리(입사일 변경 삭제 / 가져오기)에서만 불린다
- [ ] 코어에 넘기는 "오늘"이 `Asia/Seoul` 고정이고 셸의 한 곳에서만 만들어진다
- [ ] 트레이 예산이 셸의 상수 둘이며 플랫폼 지식이 그 둘로 끝난다 — 셸에 `if (isMac)` 포매팅 분기가 없다
- [ ] preload가 렌더러에 노출하는 IPC 계약이 정의되어 있다(읽기 상태 · 잔여와 내역 · 변경 커밋)
