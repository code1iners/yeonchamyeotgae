# 23. 데이터 관리 — 내보내기·가져오기·읽기 실패 화면

Type: task
Status: ready-for-agent
Blocked by: 20

## What to build

내 데이터를 확인하고, 옮기고, 깨졌을 때 되찾는 경로 전부.

- `[파일 위치 열기]`와 **2칸 들여쓰기 저장**이 "직접 열어보고 싶다"는 요구를 채운다. 저장 경로를
  설정값으로 열지 않는다([스펙 2절](../spec.md)).
- **내보내기 파일 = 저장 파일이다.** 별도 포맷을 두지 않으므로 파서·검증이 한 벌이고 v1과 v2가
  같은 코드를 쓴다.
- **가져오기는 전체 교체**이며 직전에 백업을 남기고 화면에 **"지금 데이터가 대체됩니다"** 를
  명시한다. 병합은 기각했다 — 실제 용도 둘(기기 옮기기, v2 이관)이 모두 통째로 옮기는 것이다.
- **읽기 실패 화면은 탭이 아니다**(5.5절). **팝오버 전체를 차지**하고 버튼 둘
  (`[백업에서 복구]` / `[파일 위치 열기]`)을 갖는다. **미래 버전일 때는 버튼 없이 안내만** 띄운다 —
  그 백업도 신버전이 남긴 것이다.
- **입사일을 바꿀 때** "새 입사일 이전의 휴가 기록과 조정 레코드를 지울까요?"를 묻고 사용자가
  고른다. 삭제 직전에 백업이 남는다. **거절할 수 있어야 한다** — 그래서 파서가 "입사일 이전 휴가
  기록"을 거부하지 않는다(16번).

## Acceptance criteria

- [ ] 설정 탭에 `[파일 위치 열기]`가 있고 OS 파일 관리자에서 해당 폴더가 열린다
- [ ] 저장 파일이 2칸 들여쓰기로 사람이 읽을 수 있게 쓰인다
- [ ] 내보내기 산출물이 저장 파일과 **같은 포맷**이고, 그 파일을 그대로 가져올 수 있다
- [ ] 가져오기가 전체 교체이고, 실행 전에 "지금 데이터가 대체됩니다"가 화면에 뜨며, 직전에 `data.json.bak`이 남는다
- [ ] `invalid-json` / `schema-mismatch`에서 팝오버 전체가 오류 화면이 되고 버튼 둘이 뜬다. 고를 때까지 파일에 쓰지 않는다
- [ ] `[백업에서 복구]`가 `data.json.bak`을 복원하고 정상 화면으로 돌아온다
- [ ] `future-version`에서는 버튼 없이 "앱을 업데이트하세요" 안내만 뜬다
- [ ] 입사일 변경 시 이전 기록 삭제 여부를 묻고, **거절하면 기록이 그대로 남으며 앱이 그 파일을 정상적으로 읽는다**
- [ ] 삭제를 수락하면 삭제 직전에 백업이 남는다
