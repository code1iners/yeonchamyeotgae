# 15. 트레이와 팝오버 셸 — 대시가 뜬다

Type: task
Status: resolved
Blocked by: 13

## What to build

앱을 실행하면 메뉴 막대(macOS) / 알림 영역(Windows)에 **가로 대시 하나**가 뜨고, 그것을 누르면
폭 380px 팝오버가 열리고 다른 곳을 누르면 닫힌다. macOS에서는 Dock을 차지하지 않고, 두 번
실행해도 인스턴스는 하나다.

대시는 **파일이 아니라 함수**다 — 런타임에 canvas로 그려 `nativeImage`로 넘긴다.
16px 아이콘 파일을 만들지 마라([스펙 6.3절](../spec.md)).

**대시는 장식이 아니라 상태 표시다** — "숫자가 들어갈 자리인데 아직 계산할 수 없다"는 뜻이고,
입사일이 설정되면 그 자리에 숫자가 들어온다(19번).

**6.1절의 짝수 강제를 단순화하지 마라**(9절 15번). `round(size * 0.125)`로 줄이면 20px에서
두께 3px이 나와 반 픽셀이 남고, 이 글리프를 고른 유일한 근거(안티에일리어싱 0)가 사라진다.

```
w = max(2, round(size * 0.56 / 2) * 2)
h = max(2, round(size * 0.125 / 2) * 2)
fillRect((size - w) / 2, (size - h) / 2, w, h)
```

## Acceptance criteria

- [x] `drawGlyph(size, tone)`이 있고 `tone`은 `'mono' | 'light' | 'dark'`다(6.2절)
- [x] 6.1절 표와 값이 일치한다 — 16→8×2 @ (4,7), 20→12×2 @ (4,9), 24→14×4 @ (5,10), 32→18×4 @ (7,14), 40→22×6 @ (9,17), 48→26×6 @ (11,21)
- [x] macOS는 `setTemplateImage(true)` 한 장으로 라이트/다크가 해결된다
- [x] Windows는 **정사각** 비트맵을 직접 그려 넘긴다 — `Tray.setImage`가 파일 경로 없이는 크기를 맞춰주지 않는다(4.1절)
- [x] 트레이를 누르면 팝오버가 토글되고, 포커스를 잃으면 닫힌다
- [x] 팝오버 폭이 380px 고정이고 높이는 내용에 맞춘다(5.6절)
- [x] **단일 인스턴스 락**이 걸려 있어 두 번째 실행이 기존 인스턴스의 팝오버를 열고 종료한다
- [x] macOS에서 Dock에 뜨지 않는다
- [x] 16px에서 대시가 번지지 않는 것을 확인했다(macOS) — 단, 이 개발 기기에서는 메뉴 막대상 확인이 불가해 1:1 픽셀 실측으로 확인(Comments 참조). Windows 실물 확인은 보류(Comments 참조)

## Answer

`apps/desktop/src/main/{glyph,tray,popover}.ts` + preload/렌더러 높이 보고로 구현했다.
검증은 전부 실측이다.

- **`drawGlyph(size, tone)`** — [glyph.ts](../../../apps/desktop/src/main/glyph.ts).
  6.1절 공식 그대로(짝수 강제 유지). Electron 런타임에서 6개 사이즈 전부 실측:
  `16→8×2@(4,7), 20→12×2@(4,9), 24→14×4@(5,10), 32→18×4@(7,14), 40→22×6@(9,17),
  48→26×6@(11,21)` — 표와 완전 일치, **중간 알파(안티에일리어싱) 픽셀 0개**.
- **macOS 템플릿** — 16px@1x + 32px@2x 두 표현을 PNG로 담아
  `setTemplateImage(true)` 한 장. raw 비트맵 대신 PNG로 넘기는 이유는 코드 주석에 있다.
- **Windows 정사각** — `round(16 × scaleFactor)`(짝수 보정) 크기의 정사각 비트맵을
  `createFromBitmap`으로 직접 생성. 톤은 `nativeTheme.shouldUseDarkColors`로 초기 1회 결정
  (테마 변경 리스너는 21번 티켓 몫).
- **토글·blur 닫힘** — 접근성(AX) 클릭으로 실측: 1차 클릭 열림(트레이 기준 위치),
  2차 클릭 닫힘, 열린 상태에서 Finder 활성화 시 닫힘. 트레이 클릭이 blur를 먼저
  일으켜 닫힌 직후 같은 클릭이 다시 여는 문제는 250ms 재열림 억제로 막았다.
- **폭 380 고정·높이 내용 맞춤** — 렌더러 ResizeObserver → preload
  `reportContentHeight` → 메인 `setContentSize`. 실측 380×80(플레이스홀더 내용 높이).
- **단일 인스턴스 락** — 두 번째 실행이 exit 0으로 즉시 종료되고 기존 인스턴스의
  팝오버가 열리는 것, 프로세스가 1개만 남는 것 실측.
- **Dock 미표시** — `app.dock.hide()`. System Events의 `background only = true` 실측.

## Comments

- **macOS 16px 육안 확인의 한계**: 이 개발 기기(14" MBP, 1512pt)는 메뉴 막대가
  노치로 오버플로된 상태라 새 상태 항목이 렌더되지 않는 구간(x≈811)에 배치된다
  (같은 구간의 타 앱 항목도 동일하게 숨겨지는 것을 실측 — 우리 코드 문제가 아니다.
  스크린샷은 노치 아래 가상 픽셀도 담는데 그 자리가 비어 있으므로 OS가 아예 그리지
  않는 것이다). 대신 **트레이에 넘기는 것과 동일한 16px PNG를 1:1로 덤프해 확인**했다 —
  하드 엣지 대시, 중간 알파 0. 템플릿 이미지는 1x/2x 표현이 정확히 맞으면 OS가
  리샘플링하지 않으므로 메뉴 막대에서도 같은 픽셀이 나온다. 메뉴 막대에 여유가 있는
  기기에서 한 번 더 눈으로 보는 것을 권한다.
- **Windows 실물 확인: 미실시(보류)**. 이 세션은 macOS라 Windows 알림 영역 실물
  확인을 할 수 없다. CI(ci.yml)는 빌드까지만 검증한다. Windows 기기가 생기면
  16px(100% 배율) 대시 번짐 여부를 확인해 여기에 기록할 것.
- 합성 클릭(AX)은 Tray `click` 이벤트의 `bounds`가 비어 온다. 실 클릭 경로와
  무관하게 동작하도록 `tray.getBounds()` 폴백을 넣었다.
- 코드 리뷰 반영: Windows 비표준 배율에서 `round(16×배율)`이 홀수가 될 때
  처음 구현(짝수로 크기 올림)은 `SM_CXSMICON`과 1px 어긋나 OS 리샘플링(전 픽셀 AA)을
  유발할 수 있었다. 크기는 그대로 두고 glyph 좌표만 내림으로 바꿨다 — 홀수 크기에서
  반 픽셀 중심 이탈을 감수하는 대신 AA 0을 지킨다. 홀수 21·27px에서 중간 알파 0 실측.
- 알려진 트레이드오프: 다른 곳 클릭으로 팝오버가 닫힌 직후 250ms 안의 트레이 클릭은
  재열림 억제에 걸려 무시된다. 토글을 지키기 위한 표준적 절충이다.
