# 15. 트레이와 팝오버 셸 — 대시가 뜬다

Type: task
Status: ready-for-agent
Blocked by: 13

## What to build

앱을 실행하면 메뉴 막대(macOS) / 알림 영역(Windows)에 **가로 대시 하나**가 뜨고, 그것을 누르면
폭 380px 팝오버가 열리고 다른 곳을 누르면 닫힌다. macOS에서는 Dock을 차지하지 않고, 두 번
실행해도 인스턴스는 하나다.

대시는 **파일이 아니라 함수**다 — 런타임에 canvas로 그려 `nativeImage`로 넘긴다.
16px 아이콘 파일을 만들지 마라([스펙 6.3절](../spec.md)).

**대시는 장식이 아니라 상태 표시다** — "숫자가 들어갈 자리인데 아직 계산할 수 없다"는 뜻이고,
입사일이 설정되면 그 자리에 숫자가 들어온다(19번).

**6.1절의 짝수 강제를 단순화하지 마라**(9절 15번). `round(size * 0.125)`로 줄이면 20px에서
두께 3px이 나와 반 픽셀이 남고, 이 글리프를 고른 유일한 근거(안티에일리어싱 0)가 사라진다.

```
w = max(2, round(size * 0.56 / 2) * 2)
h = max(2, round(size * 0.125 / 2) * 2)
fillRect((size - w) / 2, (size - h) / 2, w, h)
```

## Acceptance criteria

- [ ] `drawGlyph(size, tone)`이 있고 `tone`은 `'mono' | 'light' | 'dark'`다(6.2절)
- [ ] 6.1절 표와 값이 일치한다 — 16→8×2 @ (4,7), 20→12×2 @ (4,9), 24→14×4 @ (5,10), 32→18×4 @ (7,14), 40→22×6 @ (9,17), 48→26×6 @ (11,21)
- [ ] macOS는 `setTemplateImage(true)` 한 장으로 라이트/다크가 해결된다
- [ ] Windows는 **정사각** 비트맵을 직접 그려 넘긴다 — `Tray.setImage`가 파일 경로 없이는 크기를 맞춰주지 않는다(4.1절)
- [ ] 트레이를 누르면 팝오버가 토글되고, 포커스를 잃으면 닫힌다
- [ ] 팝오버 폭이 380px 고정이고 높이는 내용에 맞춘다(5.6절)
- [ ] **단일 인스턴스 락**이 걸려 있어 두 번째 실행이 기존 인스턴스의 팝오버를 열고 종료한다
- [ ] macOS에서 Dock에 뜨지 않는다
- [ ] 16px에서 대시가 번지지 않는 것을 눈으로 확인했다(macOS). Windows 실물 확인 결과는 티켓 코멘트에 기록한다
