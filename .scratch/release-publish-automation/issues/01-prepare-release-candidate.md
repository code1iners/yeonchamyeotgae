# 01: 대화형 릴리스 후보 준비와 CI 승인

**What to build:** 릴리스 담당자가 `pnpm publish-release` 하나를 실행해 저장소 상태를 확인하고,
다음 안정 버전을 선택하고, 릴리스 준비 커밋을 만든 뒤 `main`에 push하여 정확한 커밋의 CI
성공까지 확인할 수 있게 한다. 이미 준비된 미게시 버전은 재사용하고, 안전하지 않은 저장소
상태나 실패한 CI에서는 태그를 만들지 않은 채 명확히 중단한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 명령은 대화형 터미널에서만 실행되며 저장소 루트, 필수 도구, GitHub 인증, `main` 브랜치, 깨끗한 작업 트리와 `origin` 접근을 원격 변경 전에 확인한다.
- [ ] 원격 참조를 새로 조회한 뒤 behind 또는 diverged 상태에서는 pull·merge·rebase 없이 중단하고, ahead 상태에서는 포함할 커밋을 최종 확인에 표시한다.
- [ ] 현재 앱 버전과 최신 공개 안정 릴리스를 보여주고 patch·minor·major·직접 입력 선택지를 제공하며 patch를 기본 추천한다.
- [ ] 정식 SemVer가 아니거나 prerelease·build metadata를 포함하거나 기존 안정 버전보다 높지 않은 후보는 거부한다.
- [ ] 새 버전은 권위 있는 데스크톱 앱 manifest에 반영되고 `릴리스: v<version> 준비` 형식의 한국어 커밋으로 기록되며, 관련 없는 파일은 stage되지 않는다.
- [ ] 현재 manifest 버전이 미게시 상태로 이미 커밋돼 있으면 중복 버전 변경과 커밋을 만들지 않고, 그 커밋이 `origin/main`과 같으면 `main` push도 생략한다.
- [ ] 첫 원격 변경 전에 버전, 전체 커밋 SHA, 포함할 로컬 커밋, `main` push 여부와 이후 생성할 태그를 요약하고 명시적 승인을 받는다.
- [ ] `main` push는 기존 pre-push 훅을 우회하지 않으며 훅이나 push가 실패하면 로컬 준비 커밋을 보존하고 태그 없이 중단한다.
- [ ] push 뒤 정확한 전체 커밋 SHA와 push 이벤트에 해당하는 CI를 찾아 성공까지 기다리고, 검색 지연은 제한된 재시도로 처리한다.
- [ ] CI가 실패·취소·건너뜀·시간 초과 상태이거나 정확한 실행을 찾지 못하면 태그를 만들지 않고 실패 상태와 재시도 방법을 안내한다.
- [ ] 하나의 블랙박스 명령 테스트 seam이 정상 버전 선택, 이미 준비된 버전, 저장소 분기 상태, 입력 거절, 환경 실패, push 실패와 CI 성공·실패를 외부 동작으로 검증한다.
- [ ] 기존 훅 테스트, 워크플로 계약 검사와 기본 검증이 마지막 변경 이후 통과하며, 가짜 원격 테스트 결과를 실제 GitHub 게시 증거로 표현하지 않는다.
