# ADR-0002 — 날짜는 Temporal.PlainDate로 다루고, "오늘"은 Asia/Seoul로 고정한다

- **상태**: 채택 (2026-08-26)
- **결정 티켓**: [`.scratch/yeoncha-tray-app/issues/09-project-structure.md`](../../.scratch/yeoncha-tray-app/issues/09-project-structure.md) 3·4절
- **관련**: [ADR-0001 — 셸 프레임워크로 Electron을 쓴다](0001-electron-as-shell-framework.md)

## 맥락

이 제품은 **날짜 산술이 전부다.** **발생**은 `입사일 + n개월`에 생기고, **소멸일**은
`발생일 + 1년 − 1일`이며, 회계연도 기준 첫해 비례부여는 **완성 개월 수**에서 나온다.
**잔여**라는 숫자 하나가 제품이고, 그 숫자는 날짜 비교의 결과다.

그리고 **이 도메인에는 시각이 하나도 없다.** [`CONTEXT.md`](../../CONTEXT.md)의 날짜 용어
(**발생일**, **소멸일**, **입사일**)가 전부 "날"이고, 그래서 이름 규칙이 `~At`이 아니라
`~Date`다. 저장 형식도 `YYYY-MM-DD` 문자열이다.

후보는 `Temporal`(Stage 3, 환경에 따라 폴리필 필요), `date-fns`, `dayjs`였다. 그리고 별도로
"오늘"을 무엇으로 만드는가 — 시스템 로컬 시간대인가 고정 시간대인가 — 가 열려 있었다.

## 결정

**1. `Temporal.PlainDate`를 쓴다.**

**2. `temporal-polyfill`을 코어 패키지의 정식 `dependencies`로 두고, 네이티브 `Temporal`이
있는 렌더러에서도 폴리필을 쓴다.** 명명 import(`import { Temporal } from 'temporal-polyfill'`)로
통일해 **환경 분기를 0으로 만든다.**

**3. "오늘"은 고정 `Asia/Seoul`이다.** 셸이 `Temporal.Now.plainDateISO('Asia/Seoul')`로 만들어
코어에 넘긴다. **코어는 현재 날짜를 스스로 읽지 않는다.** 설정값으로 열지 않는다.

## 근거

### `Date` 기반 라이브러리를 기각한 이유는 크기가 아니라 타입이다

`date-fns`와 `dayjs`는 둘 다 `Date` 위에서 돈다. **`Date`는 시각과 시간대를 반드시 끌고
들어온다** — `new Date('2026-01-01')`은 UTC 자정이고, 음수 오프셋 지역에서 `getDate()`가
전날을 준다. 우리 도메인에 시각이 없는데 타입이 시각을 강제하면, **모든 날짜 연산이 "시간대를
잘못 다루면 하루 틀린다"는 함정을 하나씩 갖는다.** 이 앱에서 하루가 틀리면 잔여가 틀린다.

`Temporal.PlainDate`는 시각도 시간대도 없는 타입이고, 저장 형식과 1:1이다
(`PlainDate.from(문자열)` / `.toString()`).

### 산정 규칙을 실제로 돌려 확인했다 — 예외 코드 0줄이다

| 규칙 | Temporal 표현 | 결과 |
| --- | --- | --- |
| 월말 클램프 (2024-01-31 입사) | `hireDate.add({ months: n })` | `2024-02-29 → 03-31 → 04-30 → 05-31` ✓ |
| 같은 케이스의 월차 소멸일 | `.add({ years: 1 }).subtract({ days: 1 })` | `2025-01-30` ✓ |
| 같은 케이스의 연차 발생일 | `.add({ years: 1 })` | `2025-01-31` ✓ |
| `+1년 −1일`이 윤년에서 어긋나지 않을 것 | 같은 식 | 2024년 366일 / 2023년 365일 ✓ |
| 완성 개월 수 (2024-07-15 → 12-31 = 5) | `.until(d, { largestUnit: 'month' }).months` | `5` ✓ |
| 달력 격자 | `.dayOfWeek` / `.daysInMonth` / `.add({ months: 1 })` | `6` / `31` ✓ |

**월말 클램프가 `PlainDate.add()`의 기본 동작(`constrain`)과 일치한다는 것이 결정적이었다.**
산정 규칙이 요구한 것을 라이브러리가 기본값으로 이미 하고 있어 예외 처리 코드가 필요 없다.
그리고 **달력 격자는 코어의 seam이 되지 않는다** — `PlainDate`가 직접 주므로 코어에 함수를
만들 이유가 없다.

### 왜 네이티브가 있는 곳에서도 폴리필을 쓰는가

이 부분이 근거 없이는 가장 놀라운 선택이다.

| 런타임 | 네이티브 `Temporal` |
| --- | --- |
| Chrome / Edge 144+, Firefox 139+ | 있음 |
| **Electron 44의 렌더러 (Chromium 152)** | **있음** |
| **Electron 44의 메인 프로세스 (Node 24.18.1)** | **없음** |
| **Node 24 LTS (Vitest가 도는 곳)** | **없음** |
| Node 26.0.0+ | 있음. 단 Node 26은 아직 LTS가 아니다 |

즉 **같은 앱 안에서 렌더러에는 있고 메인 프로세스에는 없다.** 있는 곳에서 네이티브를 쓰고
없는 곳에서 폴리필을 쓰면 **환경 분기가 하나 생기고, 그 분기가 두 구현의 미세한 동작 차이를
숨긴다.** 잔여가 환경에 따라 다르게 나오는 경로를 열지 않는다.

폴리필을 항상 쓰면 Node 24 · Chromium 152 · 미래의 v2 브라우저에서 **동작이 완전히 같다.**
실측 크기는 **56KB min / 19.8KB gzip**으로, DMG 120.8MB짜리 앱에서 반올림 오차다.

### 왜 "오늘"을 고정 KST로 두는가

- 연차는 회사의 날짜 개념이고 회사는 KST에 산다. **소멸일이 지났는지는 사용자가 어디에 있든
  KST로 판정되어야 한다.**
- **더 센 이유는 v1과 v2가 같은 파일에서 같은 숫자를 내야 한다는 것이다.** 로컬 시간대를 쓰면
  해외에 있는 폰의 PWA와 집의 데스크톱이 **하루 다른 잔여**를 띄운다. 그리고 그게 하필 소멸을
  알아채는 두 경로 중 하나(발생분 행의 D-day)에서 갈린다.
- **설정값으로 빼지 않는다.** "진짜 단순한 앱" 전제를 통과하지 못한다.

### 왜 코어가 "오늘"을 인자로 받는가

트레이 숫자는 **자정·절전 복귀·시스템 시각 변경**에 재계산되어야 한다(스펙 4.5절).
코어가 내부에서 현재 날짜를 읽으면 **그 트리거들이 아무 효과가 없고, 검증 케이스 14건을 표로
쓸 수도 없다.** 자정 타이머도 KST 자정에 건다.

## 대안

| 대안 | 기각 이유 |
| --- | --- |
| `date-fns` | `Date` 기반. 위 "타입" 논거 |
| `dayjs` | 같음 |
| 네이티브 `Temporal`만 쓰고 폴리필 없음 | Node 24에서 동작하지 않는다. 코어 테스트가 Node에서 돌고 메인 프로세스도 Node다 |
| 있는 곳은 네이티브 / 없는 곳은 폴리필 | 환경 분기가 생기고 두 구현의 차이를 숨긴다 |
| 시스템 로컬 시간대 | v1과 v2가 하루 다른 잔여를 낸다 |
| 시간대를 설정값으로 | "진짜 단순한 앱" 전제를 통과하지 못한다 |

## 결과

- **코어 패키지의 런타임 의존성은 `temporal-polyfill` 하나뿐이다.** 이것이 워크스페이스
  경계를 pnpm이 강제하는 구조와 짝이 된다(스펙 7.1절).
- **`~Date` 이름 규칙이 타입 수준에서 뜻을 갖는다.** `expiredAt`이 아니라 `expiryDate`인 것,
  `hiredAt`이 아니라 `hireDate`인 것이 취향이 아니라 `PlainDate`라는 사실의 표현이다.
- **되돌리기 비용이 비대칭이다.**
  - 폴리필 → 네이티브: **import 한 줄.** 쉽다.
  - `Temporal` → `Date` 기반 라이브러리: **코어의 모든 날짜 산술을 다시 쓰는 것.** 그게 제품
    전부다. 이 방향은 사실상 되돌릴 수 없다.
  - 고정 KST → 로컬: 셸의 한 줄. 쉽지만 **바꾸면 v1과 v2가 다른 숫자를 낸다.**

## 이 ADR이 막으려는 것

세 가지가 전부 "최적화"로 보이는 모양이고, 근거를 모르면 되돌려진다.

1. **"렌더러에는 네이티브가 있으니 폴리필을 빼자"** → 환경 분기가 생기고 잔여가 환경에 따라
   갈릴 수 있다.
2. **"시간대를 설정값으로 열자" 또는 "로컬 시간대를 쓰자"** → v1과 v2가 하루 다른 잔여를 낸다.
3. **"Temporal은 아직 표준이 아니니 date-fns로 가자"** → 예외 코드 0줄로 통과하던 규칙 여섯
   개가 전부 시간대 함정을 하나씩 갖게 된다.

## 검증하지 못한 것

- **폴리필을 네이티브로 갈아탈 시점을 정하지 않았다.** Node LTS와 주요 브라우저에 전부 들어온
  뒤에 다시 볼 일이다.
- **`apps/web`(v2 PWA)에서 실제로 돌려보지 않았다.** v2는 현재 범위 밖이다.
